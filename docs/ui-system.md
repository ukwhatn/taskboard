# 画面の作り

レイアウトの決まり。余白、幅、揃え、折り返しは部品が持ち、画面のコードは部品を組むだけにする。Web で layout component が gap と padding を持ち、中の要素が外側の margin を持たないのと同じ考え方。何を出すか（依頼・状況・お知らせ）は `docs/ux-principles.md`、文言は `docs/ui-copy.md`。

## 原則

- **余白はコンテナが持つ。** 中に置く view は外側の余白を持たない。`padding` を書くのは部品の中だけ
- **余白は役割で選ぶ。** `Space` の値（ページ、節、塊、行、並び、カードの内側）から選び、数値を直接書かない。`Space.row + 2` のような足し算もしない。Markdown の本文の中（ブロック・リスト・コードの塊・表）は `Space` より詰めた `MarkdownMetrics` から選ぶ
- **長さの変わる文字は、折り返すか省略するかを決める。** 文字の役割（`TextRole`）が決める。横の `fixedSize` で幅を取らせない
- **大きさは中身と置かれた枠で決まる。** 高さと幅を固定の値にしない。決めてよいのは最小と最大（読める幅、押せる大きさ、パネルの最小幅）
- **標準の部品を先に使う。** 一覧は `List` と `Table`、入力は `Form`、確認は `confirmationDialog`。自前で組むのは標準に無いもの（ボードの列とカード、端末）と、測って重かったもの（空状態の `EmptyState`、帯の `BannerLayout`。「使わない書き方」）だけ
- **大きさの変わる動きを付けない。** transition と `withAnimation` は使わない。開閉・切り替え・スクロール・畳みは即時にする（アニメーションの毎フレームで、ボードの全カードを計り直していた）。動かしてよいのは、並びを計り直さない不透明度と回転だけ（チャットの発言の操作の帯と開閉の印。`ChatMotion`）。「視差効果を減らす」（reduce motion）が入っていれば、それも止める

| `WindowMetrics`・`.windowMinimum(_:)` | macOS の窓の最小の大きさ（主ウィンドウ 720×480、タスク 420×480、文書 640×480）。窓の根に置く。設定の窓は最小 760×520、開いたとき 860×640 |
| `SheetMetrics` | macOS のシートの高さと、`SheetScaffold` に載せないシートの大きさ（外観の選び方の最小の高さ 480、承認の確認 620×520〜720×640、オーケストレーターへのメッセージの高さ 300〜620、ショートカットの一覧の高さ 420〜720、コマンドパレット 640×440）。幅は `SheetScaffold` の `width` で渡す |
| `WindowRoot` | 窓の根。モデルと保存先を配り、窓の印（`\.window`）を作る。終了・再起動の確認のダイアログもここに置き、確認を出した窓に出す。新しい窓の根にはこれを付ける |
| `DeferredMount`・`MountQueue` | 重い部品を、画面が出た後の runloop で 1 回に 1 つずつ組む（1 回で組むと、初めて会話を開くタスクのパネルで主スレッドが 200 ms 余り止まった）。今はタスクのパネルの見出しのチップと帯・セッションの欄（`.first`）、会話の入力欄の帯（`.first`）、右の欄とその中身（`.later`）、全体のボードの案件の帯（`.later`。8 案件を 1 回で組むと 190 ms 止まった）に使う。組むまでの 1〜数回は置き場が大きさ 0 で空に見える。入力欄のフォーカスは帯が出たときに当てる。組む前の部品の位置へ送るときは、`MountQueue.afterQueued` で組み終えた後にもう一度送る（全体のボードのタスクを開いたときの案件への送り）。snapshot test は環境値 `defersMount` を切り、1 回で組んだ形を撮る |
| `FailureBanner` | 操作の失敗の帯。どの端末でも画面の下に出し、閉じられる。出すのは、その窓で始めた操作の失敗だけ（操作は始めに `beginAction` で窓を捕まえ、後から届く失敗もその窓に出す。窓を閉じたら捨てる）。iPhone はタブごとの NavigationStack に付ける（タブバーの上に出る） |
| `ListRowMetrics` | 一覧の行頭のアイコンの列の幅。種別で幅の違うアイコンでも題の左端が揃う。区切り線は本文の列に置き、本文の左端に揃える |
| `SheetScaffold` | 入力のシート。Mac は上に見出し、下の帯にエラーとボタン。iPhone と iPad は上のバーの左に「キャンセル」、右に確定のボタン。iPhone は題をバーの下に大きく出す（バーの中では長い確定のボタンに挟まれて切れる） |
| `LaunchChoiceFields` | 起動のエージェント・モデル・effort（起票・起動・定期起動・案件の起動の既定・オーケストレーター）。エージェントと effort は横並び、Claude Code のモデルはマシンの一覧（`GET /v1/claude`）のメニューで、頭に「デフォルトのモデル」（`--model` を渡さない）、版つきの名前は「ほかのモデル」の区分に置く。effort はモデルが受ける段階だけを出し、段階の無いモデルでは出さない。形に合わない引数はモデルのメニューを「カスタムの引数」にして引数を出し、選び直すまで変えない |
| `LabeledTextField`・`LabeledContentField` | ラベル付きの 1 行の欄。iOS の Form は TextField のラベルを出さないので、左にラベルを置く |
| `MultilineTextField` | 複数行の入力欄（チャットと会話の入力欄・題とメモのその場の編集・コメント・質問の自由記述・設定の欄）。Mac は NSTextView、iPhone と iPad は UITextView（どちらも TextKit 2）で、長い文でも打鍵ごとに全文を組み直さない。行の数の範囲で文に合わせて伸び、上を超えたら中でスクロールする。Mac のキーは ↩ が `submit`、⇧↩ が改行（`newlineOnShiftReturn: false` なら ↩ と同じ）、⌥↩ が改行。iPhone と iPad の ↩ は縦に伸びる TextField と同じく改行で、`submit` を呼ばない。枠の形は `style`（`roundedBorder` は TextField と同じ角丸の枠）、字の大きさは `font`（Mac の本文は control size に、iPhone と iPad は文字の大きさの設定に合わせる）。iPhone と iPad で自動の大文字と修正を切るのは `literal`（`.textInputAutocapitalization` は UITextView に届かない） |
| `LabeledTextEditor` | ラベル付きの複数行の欄（起動プロンプト）。iOS はラベルを欄の上に置く。Mac はラベルの右の残りの幅を全部使う（`LabeledContent` は中身を理想の幅で置くので使わない） |
| `StackedField` | ラベルを上に置き、欄を行の幅いっぱい・左寄せで出す（起票の題・リンク・備考、作業ディレクトリ）。Mac の grouped Form でラベルの右に置くと文が右に寄り、末尾の空白が見えず欄の範囲も分からなかった。文を書く欄はこれにし、選ぶもの（案件・列・横並び）はラベルを左に置く |
| `DueDateField` | 期日の選択。「なし・今日・明日・日付を指定」の横並びと、指定のときだけ日付（Mac は押すとカレンダーを出すボタン、iOS は compact の DatePicker）。「今日」は環境値 `today` |
| `LabeledSegmentedPicker` | ラベル付きの横並びの選択。iOS の Form は segmented の Picker のラベルを出さないので、ラベルを上に置く。iOS で横並びに入り切らない幅ではメニューに替わる（札は一番長い札の幅に揃うので、1 つ長いと全体が入らない） |
| `MachinePicker` | マシンの選択。1 台なら名前だけ、2〜5 台は `LabeledSegmentedPicker`、6 台からメニュー |
| `DecisionCard` | 許可と拒否の 2 択のカード（権限の確認・計画の承認）。題・中身・2 つのボタンと、あれば［常に許可］のメニュー（候補ごとに「何を許可するか（どこに残すか）」を書く）。答えられない間は理由の文を出してボタンを止める |
| `.attentionCard()` | 人の答えを待つものの囲み（問い・権限の確認・計画の承認・聞き取りの欄）。橙の地と枠 |
| `.pillStyle(selected:)` | セッションや会話を切り替える札の形。選んだものは accent の地と枠 |

## 使わない書き方

| 書き方 | 起きたこと |
|---|---|
| 長さの変わる文字に横の `fixedSize()` | 待ち理由の行がパネルを押し広げ、右端のボタンが押せなくなった |
| 向きの違う lazy な stack の入れ子（縦の Lazy の中に横の Lazy、その中に縦の Lazy） | 内側が作った分しか高さを測らず、帯の高さが実際より低くなった |
| `scrollClipDisabled()` | 枠の外に描いたカードが見えるのに押せなかった |
| 中身で決まる高さの固定（`frame(height:)`） | シートの中に余計なスクロールが出た。エラーが下に隠れた |
| 中身の幅の固定（一覧 340、欄 340 など） | 狭い画面ではみ出し、広い画面で余った |
| `GeometryReader` で測った寸法で親の大きさを決める | 測る、描く、測り直すの繰り返しで崩れる |
| スクロールの面の横の余白を `contentMargins` で取る | ウィンドウの外で描く snapshot で、初めの位置の余白が隠れた（チャットの会話、ボード）。横は中身の `padding` にする |
| 狭い欄の中に `EmptyState` | 欄に対して大きすぎた（タスクの詳細の欄の PR の失敗）。欄の中の失敗は `Banner`、空は 1 行の文にする |
| 中身の多い面を、選び直したときに `.id` で作り直して位置を戻す | 中身を全部組み直すので、全体のボードでサイドバーの案件を選び直すたびに主スレッドが 90 ms ほど使った（作り直さなければ 26 ms）。位置は `ScrollPosition` で戻す（`OverviewBoardPosition`） |
| `ContentUnavailableView` | 1 つ出すのに 100 ms 近くかかり、タスクを開く時間の半分を占めた（セッションの欄の「ターミナルを表示できません」）。同じ見た目を `EmptyState` で組む |
| よく開く画面の segmented の `Picker`（Mac） | NSSegmentedControl を作って測るのが重く、タスクのパネルを開く主スレッドの時間の 4 割（約 32 ms）を占めた（上の帯の開き方）。文字の札は `ChipButton`、アイコンだけなら塗りのアイコンと accent の色で選んだものを示すボタンにする。設定・フォームのシートのように、たまにしか開かない所は segmented のまま |
| ボタンを含む部品を `ViewThatFits` で 2 つの形に並べる | 両方の形を作って測るので、帯 1 本で 15 ms ほどかかり、ボタンも 2 つずつ作られた。窓のどこかの大きさが変わるたび（入力欄に 1 字打つたび）に測り直し、会話の上の帯では 1 打鍵に 20 ms ほどかかった。子を 1 組だけ持つ `Layout` で置き方を決める（`BannerLayout`）。ポップオーバーを持つボタンのように 2 組置けないものは、ラベルだけの見えない写しの幅と、置く所の幅を測って 1 つの形だけを置く（`ConversationTopBar`） |
| 中身の形を選ぶ帯の幅を、その帯に付けた `onGeometryChange` で測る | 中身が入らないと帯が中身に押されて広がり、測った幅も広がるので、入ると判定し続ける。広がった帯は親の stack ごと画面より広げ、iPhone の会話の画面で一覧・入力欄・下の帯の左右が切れた（上の帯に差分の数が出る会話）。帯を `FillWidth` に入れ、その幅を測る |
| 中身の高さが後から変わる札を `LazyVGrid` に並べる | 見張り盤で広げた札が、メッセージを読み込んで伸びた後も行の高さを測り直さず、下の節に重なった。並ぶ数が限られる格子は、行ごとの HStack を VStack に積み、列の幅は面の幅から決める（`ConversationBoardSurface.grid`） |

## 幅と並べ方

- 列を揃えるのは `Grid`。並べて入らなければ次の行へ送るのは `FlowRow`
- 形（設定を押して開くか並べるか、一覧と中身、シートか popover か、余白）は size class で決め、機種（`AppModel.isPhone`）は「できること」（iPhone のタブの殻、タスクの開き方を選べるか、ショートカットの区分、端末の登録の platform）だけに使う。狭い iPad は形が iPhone と同じになり、殻はサイドバーのまま。幅で形を変えるのは size class と、子を 1 組だけ持つ `Layout`（`BannerLayout`）。`ViewThatFits` は中身の軽いもの（文字だけ）に限る（「使わない書き方」）。枠の大きさに合わせるのは `containerRelativeFrame`。測った幅で縦横を替えるときは、同じ子の配置だけ替える（セッションの欄と右の欄は `SessionSplit`。「使わない書き方」）
- スクロールの面の縦の余白は `contentMargins`、横の余白は中身の `padding`（「使わない書き方」）
- 独自の並べ方は `Layout`（ボードの列など）

## 選択の形

選ぶ数と頻度で決める。

- 2〜5 個から毎回か頻繁に選ぶものは横並び（`segmented` か `ChipButton`）。Mac でよく開く画面（タスクのパネル）は segmented にしない（「使わない書き方」）
- マシンは、案件の追加・定期起動のフォーム・オーケストレーターへの指示のどれも `MachinePicker`（1 台なら名前だけ、2〜5 台は横並び、6 台からメニュー）
- 数が変わるもの、6 個以上のもの、まれにしか変えないものはメニュー
- 数百あるものは検索できる一覧
- 自由入力は候補を付けた欄（作業ディレクトリは `WorkdirField`。ブックマークと最近使ったものを候補に出す）

## 端末ごとの作法

- 設定: 端末ごとの設定（端末・チャット・通知・表示）と、マシンの設定（セッション）は変えたらすぐ反映する。マシンの設定は押した値を先に出し、失敗したら戻して帯で知らせる（`PendingValue`。続けて押し直していたら、前に押した値の失敗では戻さない）。案件の設定（名前・マージしたら・列・起動）は案件の一覧から 1 件開き、下の保存の帯の［保存］で 1 回に送る。保存していない変更があるまま区分を移る・一覧へ戻るときは「変更の破棄」で確かめる。設定の窓を閉じたときは確かめず、下書きをアプリを終えるまで残して、次に開くと続きから編集する（`AppModel.settingsBoardDrafts`）
- 利用状況（設定の［利用状況］、`UsageSettings`）: 読むだけの区分で、Form にせず `Page` に節を並べる。上の行に期間（24時間・7日・30日の segmented）と、Mac が 2 台以上なら Mac のメニュー（すべてのMac と各 Mac）、［再読み込み］。初めの読み込みは区画のスピナー、読み直しは右のスピナーで、前の絵を残す。読めなかった Mac は帯で知らせ、読めた Mac だけで描く。グラフは Swift Charts で、系列の色は `UsageChartPalette` の決まった順（ライト・ダークとも色覚の型ごとに確かめた 4 色）。系列が 2 本以上なら凡例を出し、トークンは表を添える。時間のグラフは触れた区切りの値を出す（`chartXSelection`）
- チャット・PR の本文・文書のリンク: `[文字](URL)` と素の http・https の URL（コードの中は除く）を押すと、既定のブラウザで開く。`taskboard://` はアプリの中で開き、ファイルと相対パスは開かない（会話のファイルはファイルの札から開く。`MarkdownView` の `openURL` と文書の `DocumentWebController` が、どちらも `LinkDestination` で振り分ける。文書は押したリンクだけを開き、script などの遷移は開かない）
- 会話の設定の書き込み: 読む画面のシートの中で、engine が書ける設定（Kit の `supports(edit:)`）を `edit_settings` で書く（`ConversationSettingsEditors.swift`）。権限の規則は外せる行（`editable`）に［規則を削除］、下に「規則の追加」（種類・規則・保存先）と sandbox の節（動き方と、sandbox で動かせないコマンドを外で動かすか。上の層で固定なら押せない）。フックは書き換えられる行（`editKey`）に［編集］［削除］（削除は「フックの削除」で確かめる。中身をアプリが持たず戻せないため）と［フックを追加］。追加と編集は同じシート（出来事・対象・種類・中身・タイムアウト・保存先）。メモリは自動のメモリとその整理の切り替え、skill は行ごとに状態を選ぶ。切り替えと選択は押した値を先に出し（`PendingValue`）、書いたら読む画面をすぐと 3 秒後に読み直す（CLI が書いたファイルを読み直すまで間がある）。断られたら理由の種類（`reason`）から原因と対処を組み、CLI の英語の文は出さない（`ConversationSettingsText.failure`）。書けたが今の会話に効かない（`overriddenBy`）か、会話を終了して再開すると効く（`needsRestart`）ときは、シートの下の帯に案内を出す（`SheetScaffold` の `notice`、`ConversationSettingsText.notice`）。止まった会話では書かない

- タスク画面の右側: 中央の札とチャットの右（並べて入らない幅では下）に、パネル（状態・文書・作業項目・差分）を開いて格子に並べる（`TaskSideArea`）。上の帯のボタンで欄を開け閉めし（開いている欄のボタンは色付き）、各欄の頭に題と［広げる］（その欄だけを右側いっぱいに。もう一度押すと戻す）・［閉じる］を置く。並べ方は、1 つなら全部、2 つなら上下、3 つ以上は幅があれば 2 列（左に多い方）、狭ければ 1 列で縦に積む（`SidePanelArrangement`）。右側を下に重ねる幅では欄を 1 つだけ出し、上の帯のボタンで替える（［広げる］［閉じる］は出さず、開いている組も書き換えない）。iPad で並べて入らない幅では、重ねずに帯だけを下に置き、帯の先頭の［会話］と欄のボタンで会話と欄を全体で入れ替える（`SessionSplit` の `swap`。会話の view は枠の外へ送って作り直さない。入力欄へのフォーカスの要求で会話に戻す）。欄どうしの境目と、中央と右側の境目は動かせる（中央との境目はダブルクリックで既定の幅に戻す）。開いている組・高さの重み・列の割合（`SidePanelSet`）と右側の幅は `AppDefaults.store` に残す。人が選ぶまでは差分だけを開く（`SidePanelSet.shown`）。中身の無い欄は開いていても空の案内を出す。欄は欄の id で並べ、自前の `Layout` で置くので、1 列と 2 列が替わっても作り直されない。状態の欄は、会話の環境・コンテキスト・利用枠・コネクタ、メモ、PR（リンクした PR の詳細。複数ならチップで切り替え）、終了したセッション（紐づけの記録だけが残ったセッションの［再開］と終了した会話の［開く］を、新しい順に 1 つの節に並べる。`FinishedSessionList`）、再開の予定（タスク宛てとタスクの会話宛ての、待っているものと失敗したもの。時刻・仕掛けたときの文・届け先の会話・失敗か試し直している理由）、PR・issueの監視（続いているものとタグに入って終えたもの。対象・文・条件・取得できないこととタグに入ったこと）、定期起動（このタスクに結んだものと各回、［定期起動を追加］）で、中身の無い節は出さない。予定と監視は読むだけで、操作は置かない（作る・取り消すのは MCP の `wake_*`・`watch_*`）。止まった会話と終了した会話の行には、いちばん早い待っている予定の時刻を「{時刻}に再開」で添える（`AppModel.nextWakeText`。帯の札は幅を変えないよう help と読み上げにだけ入れる）。委譲先は札で見るので、この欄には出さない（会話の上の帯の［状態］のポップオーバーには出す）。会話の上の帯の［状態］［差分］（`/status`・`/diff` も）は `AppModel.showSidePane` で対応する欄を開き（開いていればそのまま、ほかの欄を広げていれば戻す）、見出しのチップと通知の PR は `prFocusRequest` で状態の欄を開いて PR の節まで送る。帯のボタンで右側ごと隠せ、この端末に覚える。右側が隣に無い画面（オーケストレーター・タスクなし・右側を隠したとき・iPhone）では、［差分］はシート、［状態］はポップオーバー、端末は会話の下に出す。iPhone のタスク画面は文書・作業項目・状態・差分を切り替えて 1 つを出す（`TaskSidePane`）
- 作業項目: 依存（`dependsOn`）で段に分けて上から並べ（`WorkItemGraph`）、段の見出しに「2段目・3件を並行」と出す。依存の線は行の左の溝に出元ごとに 1 本の縦の筋で引き、線の先に矢じりを付ける（`WorkItemGraphView`）。行は画面に出ているものだけを配置し（`LazyVStack`）、線は行ごとに自分の高さの分を `Canvas` で引く（通る・出元・枝・線の先を `WorkItemGraph.Row.marks` に先に求め、状態の印の位置は行の中の `anchorPreference` で受ける）。全部の行の位置を集めて 1 枚で引くと、300 行の欄を開くたびに全部を配置して 100〜400 ms 止まった。行の範囲が重なる線は別の筋に置き、溝の幅は `WorkItemGraphMetrics.gutterLimit` までで、筋が多ければ詰める。完了と見送りは題を灰色にして出元の線を薄く引き、先頭から全部終わった段は「完了したN件を表示」の 1 行に畳む。行を `opacity` で薄くしない（300 行で配置と描画が 50 倍ほど遅くなった）。依存が無ければ段が 1 つで、見出しも線も無く計画順の一覧と同じ。「すべて」以外で絞り込んだときは計画順の一覧で出す。まとまり（`group`）のある計画では、絞り込みの下にまとまりごとの「済んだ数 / 全部」を 1 行に並べ、今のまとまりを太字にする（`WorkGroupProgress`。並びは依存の段のまま）。題の前には短い番号（`code`）を付ける（`WorkItem.codedTitle`）。追加の欄は打った文字を自分で持ち、打鍵で一覧を組み直さない。行（`WorkItemRow`）は `Equatable` にして `.equatable()` で包み、1 件の状態が変わってもほかの行を描き直さない
- 会話が置く部品（`PanelPlaces.swift`。場所は Kit の `PanelPlace`）: 部品の無い場所は何も描かない（空の枠・見出し・余白を出さない）。帯（`PanelBand`）は `TaskHeader` の最後の行で、計器を名前・値・基準で 1 行に並べ、補足は help と読み上げに入れる。会話の頭（`PanelHead`）はタスクのパネルの左の会話だけの、上の帯と会話の一覧の間に置き（右に並べた会話には置かない）、会話の列（`ReadableWidth.chat`）に揃え、高さは会話の欄の 3 分の 1 まで（超えた分は中で送る）。見出しの行を押すと折りたたみ、開閉は `AppDefaults.store`（`taskPanel.headCollapsed`。タスクによらず 1 つ、iPhone は初めに折りたたむ）に残す。入力欄の上（`PanelComposerDrafts`）は送る文面を `ConversationComposerArea` の前に置き、高さは会話の欄の 3 分の 1 まで（会話の頭と合わせても一覧に 3 分の 1 を残す）。右の欄の部品は `SidePanel.part` で、部品のあるタスクだけ帯のボタンの区切りの後ろに出し、人が開くまで閉じている（開いている組は端末で 1 つなので、部品の無いタスクでは組から外さずに出さない）。iPhone は帯を題の下、会話の頭を「会話」の節の上、右の欄の部品を欄の切り替えの最後に置く。どの場所も会話の view の外の view が部品を読むので、部品が変わっても会話の view は描き直さず、作り直さない。種類ごとの描き手は `OverviewPanelParts.swift`（`PanelPartContent`）で、色は `PanelTone` が当て、強い色は attention と failed だけにする
- 端末とシェルの欄: 会話の作業フォルダのシェルは、会話の上の帯の［ターミナル］で開け閉めする（`AppModel.terminalDock`。欄の持ち主は会話の `ConversationKey`）。開くとシェル（生きていれば前と同じシェル）を起こして繋ぎ、閉じるとシェルを止める（次に開くと新しいシェル）。シェルで `exit` すると欄ごと消える。起こしている間は「シェルを起動しています…」、起こせなければ欄の中に失敗の帯と［やり直す］。タスクの画面では、左の会話のシェルを会話と右の欄の下に全幅で置き（`TaskTerminalArea`。右の欄を隠しても同じ所）、上の境目のドラッグで高さを変えて `AppDefaults.store` に残し（`TaskTerminalArea`・`TerminalDockMetrics`。ダブルクリックで既定の 320 pt に戻す）、右に並べた 2 つ目の会話のシェルはその欄の下に出す。オーケストレーター・タスクなしの画面は会話の下の欄（`ConversationStage`・`DockingStage`・`TerminalDock`）。開いたままほかの所を操作できる。iPhone は欄を置かず、シートで開く（`ConversationTerminalSheet`。閉じてもシェルは残る）
- 対応待ちの［非表示］: カードの右クリックの「対応待ちを非表示」。タスクの見出しには待ち理由と対応待ちの帯を置かない（同じことを会話の中の権限・質問のカードが出していて、手を打てるのはカードだけ）。そのタスクの無視していない対応待ちを全部無視し、通知・Dock のバッジ・サイドバーの札から外れる（項目が変わるとまた出る）。押したらすぐに消し、daemon が断ったら戻して帯で知らせる。お知らせの既読と、無視した項目を戻す画面は置かない
- 端末のクリックと選択（Mac）: ドラッグで文字を選ぶ。選んだ文字は ⌘C（［編集］>［コピー］）か右クリックの「コピー」でコピーし、右クリックの「ペースト」は ⌘V と同じ経路で入れる（`TaskboardTerminalView`）。右クリックはシェルに送らない
- 使っていない worktree の削除: マシンの行の右クリック（iPhone は長押し）の［使っていないworktreeを削除…］から `SheetScaffold` のシートで開く（`WorktreeCleanupSheet`。書き込めない接続先では押せない）。開くと daemon の `GET /v1/worktrees` を読み、repo ごとの節に並べる（repo の本体の checkout は出さない。読めなければ一覧を出さず、下の帯に失敗だけを出す）。消せるものを先に、行の先頭の印（Mac はチェックボックス、iPhone・iPad はスイッチ）で選ぶ。初めは全部外す。消せないものは印を押せず、枝の名前・パス・比べ先・理由（`WorktreeBlocker.text`。複数あれば全部）を出す。［削除］は選んだ件数を確かめる `confirmationDialog`（題「worktreeの削除」、本文に消える worktree のブランチとパスを 1 件ずつ）の後に `POST /v1/worktrees/remove` を呼び、シートを結果の一覧に替えて 1 件ずつ出す（消した・ブランチが残った・断られた・失敗。git の文はそのまま添える）。一覧の判定は表示のためで、daemon が削除のときに読み直す
- タスクの削除: パネルの上の帯のゴミ箱、カードの右クリックの末尾、iPhone のタスクの画面のツールバーのメニュー。確認は置いた所の窓に出す（`taskDeleteDialog`）。表示用のデータでは出さない
- タスクの編集: 編集のメニューは置かず、それぞれの表示の場所で直す（`InlineField`）。題は見出しを押すとその場で欄になり（`TaskHeader`。Mac はホバーで枠が出る）、メモはサイドパネルの状態のメモ（空なら「メモはありません」）を押すと欄になる（`TaskSidePane`）。↩ か欄の外を押すと保存、Esc で元に戻す（メモは ⇧↩・⌥↩ で改行）。題は空白だけなら保存せず元の題に戻し、メモは空にすると消す。iPhone と iPad は長押しの［タイトルを編集］［メモを編集］からも入る。リンクはチップの並びの末尾の［リンクを追加］を押すと URL の欄になり、↩ か欄の外で足す（空白で区切って複数可）。紐づくセッションは見出しの会話の札の行（チップと 1 段に入らない幅ではチップの下の段）とセッションの空状態の［セッションを紐づける…］（iPhone はタスクの画面の会話の節の末尾）から `SheetScaffold` のシートで選ぶ（`taskSessionSheets`）。リンクのチップと PR の節のチップの右クリック（長押し）の［このタスクから外す］で外し、確認は挟まない（URL を足し直せる）。表示用のデータでは出さない

## 確かめ方

- snapshot test は、大きさ（Mac の幅 1280、1728、2560）、外観（ライト、ダーク）、負荷のかかるデータ（長い題、長い待ち理由、カードの多い列、空、エラー）の組で撮る（`App/Tests/`）
- 実ウィンドウは `scripts/ui/` のスクリプトで撮り、クリックとスクロールを送って確かめる。どれもアプリを fixtures（既定は `stress`）で別に起動するので、本物の daemon とセッションには触れない。先に `scripts/build-mac.sh` でビルドしておく
  - `scripts/ui/check-board.sh [幅] [高さ]`: 全体のボードの見えているカードを 1 枚ずつ本当にクリックし、押したカードのタスクが開くかを `/state` で確かめる。開かないカードと、別のタスクが開いたカードを出して失敗する
  - `scripts/ui/check-panel.sh [番号] [文書の id]`: タスクのパネルを開き方 4 種（並べて表示・大きく表示・中央に表示・別ウインドウ）と幅 3 種で撮り、文書の画面も撮る。タスクを開いて窓の高さが変わったときと、「閉じる」が窓の外に出ていれば失敗する。崩れは画像を見て確かめる
  - `scripts/ui/capture.sh <名前> [taskboard://…] [幅…]`: 幅ごとに撮る（既定 1280、1728、2560）。`List` の画面（サイドバー、一覧、設定）はこちらで見る。`APPEARANCE=dark` でダーク
  - `scripts/ui/uiprobe.swift`: 上の 2 つが使う道具（窓の番号、読み上げの木からカードの位置）。シートの中のボタンは `/click` では押せない（後ろにある窓の最初のクリックは窓を前に出すだけ）ので、`uiprobe press <pid> <名前>` で読み上げの木から押す
  - アプリは起動の直後に 1 度だけ前面に出し、すぐ前面を元のアプリに返す（後ろで起動したアプリは、前面に出るまで最初の窓を作らない。2026-10-06 に実測）。窓はほかの窓の後ろに置く。押す・送るはアプリの debug の口（`/click`・`/cursor`）がアプリの中でイベントを作って渡すので、マウスとキーボードは動かない。ほかの作業をしながら回せる（`scripts/ui/lib.sh`）。初回はアクセシビリティの許可が要る
  - `scripts/ui/perf.sh`（滑らかさの計測）だけは、隠れた窓の描画が止まるので窓を前に出す（アプリは前面に出さない）
  - 本物のデータで確かめるときは `SCENARIO=`（空）。開いたタスクの端末は操作権を取り、ほかの端末で開いている会話のシェルの大きさがアプリの枠に合わせて変わるので、シェルを開かない
  - ⌘ を押しながらのクリックと、トラックパッドの横のスクロールは、この方法では作れない。手で確かめる
- iPad と iPhone はシミュレータで撮る（iOS の snapshot test の target は持たない）
  - `TextRenderer` で描くもの（チャットの行内のコードの角丸の地）は、snapshot test と debug の `/screenshot`（どちらも `cacheDisplay`）に写らず、普通の文として描かれる。シミュレータの `simctl io` で見る
- 画面を直したら、snapshot の PNG と実ウィンドウの画像を見てから完了にする。snapshot test の通過だけでは完了にしない
