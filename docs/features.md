# できること

## ボード

- 案件ごとの列（未着手、作業中、レビュー中など）にタスクのカードを並べる。列は案件ごとに変えられる
- すべての Mac の案件を 1 画面に並べる。マシンや案件ごとに絞ることもできる
- Mac のホームは、すべての Mac の会話を札で並べる見張り盤と、列のボードを ⌘B で切り替える。見張り盤は会話を対応待ち・実行中・未読・待機に分け、権限の確認・計画の承認・選択肢 1 問の質問には札から答えられる
- カードに、結んだ PR と Jira の課題の状態、作業項目の進み、待っている理由を出す
- PR の状態に合わせてカードを進める。PR を出したら「レビュー中」へ、マージしたら案件で決めた列（「デプロイ中」か「完了」）へ

## セッション

- カードから Claude Code か Codex を起動する。作業ディレクトリと最初のプロンプトを選べ、モデルと effort も選べる
- 作業項目にまとまり（M3 のような段階）と短い番号（M3.6・D3）を付けられる。作業項目の欄はまとまりごとに進みを出し、番号は作業項目の欄・会話の画面・タスクの詳細で同じ表記で出る
- 最後の応答の頭の 1 文を、見張り盤の札・iPhone の一覧・ボードのカードに出す
- 会話（主に lead の会話）は、タスクの画面の 4 か所に部品を置ける: 見出しの下の帯に計器 4 個、会話の上に表・計画・図・グラフ・HTML のどれか 1 つ（折りたためる）、入力欄の上に承認を待つ送る文面 2 件、右の欄に 1 つ。部品の無いタスクの画面は何も変わらない
- 会話をチャットの形で読み書きする。画像を添えて送れ、生成中の文と思考もその場で出る
- 入力欄のマイクを 1 回押すと（Mac は ⌥Space でも）、もう一度押すまで聞き続ける（会話を切り替えても止めず、文はそのとき開いている会話の入力欄に入る）。話している間は確定前の文を入力欄の下に薄く出し、2 秒黙るとその区切りを端末の中の Whisper で文字にして入力欄に入れ、会話の文脈を付けて Claude で校正した文に置き換える。最後に「送信」と言うと、合図を除いた文を校正してから送る。会話が問いの回答を待っていれば、選択肢の名前か番号で答えられる（一致しなければ自由記述の回答）。合図の無い文は送らない。押し続けると離すまで聞く。音声は端末の外に出さない（校正には文字にした文と会話の文脈を送る）
- 会話から、差分・フォルダ・ターミナルを開ける。端末で開いたセッションの画面は [libghostty](https://github.com/ghostty-org/ghostty) で描く
- 会話の途中から分ける（フォーク）、前の発言まで戻す（巻き戻し）
- しばらく動いていないセッションを止め、あとで同じ会話から再開する

## エージェントとのやり取り

- エージェントは MCP のツールでカードを進め、作業項目を更新し、計画書や報告を文書として載せる
- AskUserQuestion と権限の確認に、会話の中のカードで答える
- 人は文書にコメントを付けてレビューを返す。返事はセッションに人の発言として届く
- エージェントは判断を待つ質問と送る文面（Slack・メールの文案）を、前提を書いた文書の本文の中に置く。人は前提を読んだその場で選択肢を選び、文面を編集して承認の印を付け、文書の下の帯の［送信］で回答と承認をまとめて送る（会話には 1 通で届く）。タスクの右の欄の「判断待ち」と受信箱から、本文のその欄へ移れる。文章や設定の書き換えを見せるときは、修正前と修正後を本文の中に左右に並べ（狭い幅では上下）、変わった部分に印を付ける
- 文書の本文の mermaid の図とコードの色付け（highlight.js）は、アプリに同梱したもので描く（ライトとダーク）。外部の CSS・画像を読むモックは、開くと帯で読み込み先のホストを出し、［読み込む］を押した文書だけ読み込む（文書ごとに覚え、新しい版でホストが増えたら聞き直す）
- 文書の版は［前の版との差分］で、前の版からの行ごとの差分（1 列）を読める。本文は［ファイルに書き出す…］で markdown・HTML のまま保存でき、この Mac の文書は［Finderで表示］［エディタで開く］（既定は VS Code、［設定］>［表示］で URL を変えられる）で元のファイルを開ける
- 会話がどこまで自分で決めてよいか（委任範囲）を、7 つの項目（実装の進め方、issue・チケットの更新、範囲外の不具合の起票、レビューの依頼・マージ、社外・他チームへの投稿、費用、削除・戻せない操作）ごとに［委任］［報告のみ］［確認］で決める。案件の設定で初期値を決め、タスクの「状態」の欄で上書きする。会話は範囲の内のことを問わずに決める（［報告のみ］の項目は、決めたことを応答で報告する）
- Slack で `@taskboard` に頼むと、オーケストレーターか、チャンネルに対応づけたタスクのセッションに届く。エージェントはそのスレッドに返信できる。メッセージのメニューの［taskboardに送る］からは、bot を入れていないチャンネルのメッセージも、送り先のタスクと指示を選んで送れる（返信は DM に届く）。Slack の上のバーやチャンネルの横に開いたアプリの画面で頼むと、返事は自分にだけ見え、横で開いていたチャンネルの届け先に届く。セッションが動いている間は Slack に「作業中」と出る。Slack アプリは案件ごとに設定する
- 質問と権限の確認は、アプリを閉じていても iPhone と iPad に通知が届く。権限の確認は通知から許可か拒否を選べる

## 一覧と自動実行

- タスクにリンクした PR の CI・レビュー・中身をタスク画面で見る。どのタスクにも結ばれていない PR は一覧に並べず、通知・URL から開いたときだけマシンの「タスクなし」の画面で開く
- Claude Code と Codex の利用枠の残り（Claude Code は 5 時間と 1 週間の枠）を出す。枠を使い切ったアカウントの代わりに、残りのある別のアカウントで起こせる
- cron か間隔で定期起動する
- タスクに結ばない、何でも頼める窓口の会話（オーケストレーター）に指示する
