# daemon の仕様

各 Mac に常駐する daemon（`taskboard serve`）の動きと API。全体のしくみは [architecture.md](architecture.md)、ビルドと確かめ方は [development.md](development.md)。

## コマンド

```sh
.build/debug/taskboard serve                      # 前景。127.0.0.1:5780
scripts/install-cli.sh                            # ビルドした実行ファイルを support ディレクトリの bin/ に写して署名し（team の証明書、無ければ ad hoc）、~/.local/bin/taskboard と launchd の job をそこへ向けて daemon を起こし直す。入れ替えはこれで行う
.build/debug/taskboard install-launchd            # ~/Library/LaunchAgents/ に daemon（uk.whatn.taskboardd）と agent host（uk.whatn.taskboard-agent-host）の plist を作って load。前の版の herdr server の job（uk.whatn.taskboard-herdr）が残っていれば降ろして plist を消す
.build/debug/taskboard debug state                # 動いている daemon の /v1/state
.build/debug/taskboard import taskherd            # ~/.local/state/taskherd/tasks.json をボード "default" に取り込む（冪等。--file / --config / --board）
.build/debug/taskboard backup --label manual      # ~/Library/Application Support/taskboard/backups/ に 3 世代
.build/debug/taskboard restore <file> --verify-only   # 検証だけ。daemon を止めてから本番の restore
.build/debug/taskboard apns status                # APNs の鍵が入っているか（中身は出さない）。install・remove・check・test は「iPhone・iPad への通知」
.build/debug/taskboard conversation check         # Claude Code を haiku の短い会話で通し、通った版を host の会話に使う版として記録する（codex は --engine codex。下記「host の会話」）
.build/debug/taskboard conversation start --task 172 "質問"   # host の会話を起こす（codex は --engine codex。委譲先は --parent-from-env --notify、--disallowed-tools・--worktree-branch・--title も渡せる）。list・send・watch・answer・control・commands・fork・rewind・diff・shell・run・run-cancel・prewarm・stop・close・resume・delete・rebuild-search は --help
```

## host の会話（agent host）

Claude Code を stream-json（`-p --input-format stream-json --output-format stream-json`）で起こし、daemon が出来事を読む会話。CLI の子を持つのは daemon でなく agent host（`taskboard agent-host`、launchd の `uk.whatn.taskboard-agent-host`）で、daemon を入れ替えても会話は止まらない。

- host: このユーザーが画面にログインしていれば（`/dev/console` の持ち主が自分。ssh から実行しても）gui の domain に、していなければ Background の `user/<uid>` に置く（`install-launchd`）。Background からは login keychain がロックされて見え、Keychain にだけ入る MCP の OAuth（`/mcp` で認証したもの）が会話で読めなかった。画面にログインしていない Mac（FileVault で自動ログインできない Mac）は gui でも Keychain が開かないので、`~/.claude/.credentials.json` を読む Background に置く。support ディレクトリの `agent-host/`（700）に `host.sock`（600。繋いだ相手の UID が違えば切る）と `host.lock` を置く。起動するとまず `host.lock` を `flock` で取り、取れなければ別の host が動いているので終わる。次に、本人のプロセスのうち親が launchd（pid 1）で env に `TASKBOARD_CONVERSATION_ID` を持つもの（前の host が落ちて残った子）の process group に TERM、5 秒後に KILL を送ってから socket を作り直す。env は `KERN_PROCARGS2` で読む。OS の実行ファイル（/bin の sh や sleep）の env は同じユーザーでも読めないので、この方法では探せない（Claude Code と node は読める。2026-10-19 に実測）
- 子の出力は行ごとに番号を振って 32MB まで控え（1 行は 16MB まで。超えた行は捨てて `oversize` で知らせる）、daemon が繋ぎ直すと番号で続きから送る（控えから落ちた分は `gap`）。daemon が起き直したら `list` の子を記録と突き合わせて引き取る（`ConversationService.connected`）。会話を起こす前には `list` を引き、自分の key の生きた子があれば起こし直さずに引き取る（突き合わせより先に回答・知らせの配達や画面が起こしに来たとき。起こし直すと host が「動いている」で断る）。突き合わせでは、止まった扱いなのに host で子が生きている会話も引き取り直し、記録の「起こせなかった」を消す。引き取った会話は控えを頭から読み直す。読み直しの間の生成中の差分は購読に流さず、読み終えた時点で終わった発言が届いていない block だけを、届いた分の文を 1 つの差分にして出す（`ReplayedStream`。流すと、入れ替えの直後に開いた画面に過去の発言が 1 文字ずつ流れ込む）。標準エラーは `agent-host/logs/<key>.log`（600、1MB で 1 世代回す）。1 本の接続の要求は、同じ key の要求だけを届いた順に処理し、key をまたいでは並べて処理する（`signal` と key の無い要求は順を待たない）。stdin を読まない子への `write` は終わらないので、順に待つと、ほかの会話の hook の答えまで止まって CLI の 30 秒の時間切れで発言が捨てられていた
- 入れ替え: `install-launchd` は host が動いていれば入れ替えない。plist が変わっていても、動いている会話があれば入れ替えずにそう出す。daemon は host の protocol の版（`AgentHostWire.protocolVersion`）が自分と違えば、`list` で動いている子を取ってから `drain` を送り、host は新しい起動を断って、子が全部終わってから終わる（launchd が新しい実行ファイルで起こし直す）。待っている間は `MachineInfo.agentHost` の `draining` が true で、`remaining` に動いている会話の id が載る（MCP の `health` にも出る）。host の動きを変えたら版を上げる
- 前の host が残した子: host は子を別の process group の頭にするので、host が落ちても子は残る（親が launchd になる）。起き直した host は bind の前に、親が launchd で、env に会話の印（`TASKBOARD_CONVERSATION_ID`）と自分の置き場の印（`TASKBOARD_AGENT_HOST`。host が子に渡す）を持ち、アプリ（`.app` の中の実行ファイル）でないものの group を止める（`OrphanedChildren`）。会話の印は会話のシェルから起こしたものすべてに受け継がれるので、会話の印だけでは選ばない。一時の置き場の host が、本物の host の会話のシェルから `open` で起こしたアプリと切り離したスクリプトを止めたことがある
- 起動を断られ続ける job・読み込まれていない job の登録し直し: launchd から起こされた daemon は host の job を、host は daemon の job を、30 秒ごとに `launchctl print` で見る。動いておらず最後の終わり方が 78（EX_CONFIG）のまま 2 回続けて見えたら、`launchctl bootout` と plist からの `bootstrap` で登録し直す。`~/Library/LaunchAgents` に plist があるのに gui・user のどちらの domain にも読み込まれていないのが 2 回続けて見えたら、plist の `LimitLoadToSessionType` が Background なら `user/<uid>`、ほかは `gui/<uid>` に `bootstrap` する（`LaunchdJobRepair`。Studio を macOS 27.2 に上げた再起動の後、ssh で入れた Background の herdr と host が読み込まれず、セッションも会話も起こせなくなった）。再起動の後の LaunchAgent は BTM が実行ファイルのハッシュに結んだ起動の制約（managed LWCR）を持ち、ビルドし直した実行ファイルを AMFI が「Launch Constraint Violation」で断る。launchd は BTM で制約を直そうとするが、BTM の項目が作り直されていると「Unable to get updated LWCR」で直せず、10 秒ごとに 78 を繰り返す（2026-10-25 に daemon が 8 時間止まった。`install-launchd` で戻った）。手で動かした daemon と一時の host は見張らない（`XPC_SERVICE_NAME` が自分の label のときだけ）
- 使う CLI: `taskboard conversation check` が通した版だけ（`agent-host/verified-cli.json`、600）。check は使い捨ての作業フォルダで haiku の会話を 1 本起こし、送信・Stop の hook での続行・フォーク（`--fork-session` と `--resume-session-at`。写した transcript に元の uuid が残り、地点の後の行が無い）・`rewind_files` の dry run（書かせたファイルが変わるファイルに出る）・AskUserQuestion への答え・defer と `--resume` での答え・interrupt・`mcp_status`・`get_context_usage`・繋ぎ直しての `initialize` の送り直し・止める、の 13 段を通す（30 秒ほど）。stream-json で届いた発言と返答の uuid が transcript の発言の id（履歴の読み方と同じ `TranscriptParser`）に全部あるかも確かめる。記録の形（`VerifiedCLI.currentFormat`、今は 2）が違う記録は通していないものとして扱うので、上げたら各 Mac で回し直す。確かめの会話は画面に出ていないので、defer の段の外では問いの defer を切る。作業フォルダと transcript は終わったら消す。通した版が無ければ会話を起こさない（409 `claude_unverified`）。`TASKBOARD_CONTRACT_CLAUDE=1 swift test --filter ClaudeContractTests` も同じ会話を回す
- codex の CLI: `taskboard conversation check --engine codex` が通した版だけ（`agent-host/verified-codex.json`、600。実体は `~/.codex/packages/standalone/releases/<版>-<target>/bin/codex`）。check は使い捨ての作業フォルダで codex の既定のモデルの会話を 1 本起こし、`thread/start`・送信（発言の uuid が item の `clientId` に返る）・確認ありで `touch` の承認を許可する・`turn/interrupt`・`thread/tokenUsage/updated`・控えの読み直しでの引き取り・止める・止まった thread を別の app-server で `thread/items/list`・`thread/fork` の thread を戻して送る、の 9 段を通す（30 秒ほど）。作った thread は終わりに `thread/archive` する。通した版が無ければ codex の会話を起こさない（409 `codex_unverified`）
- 版の自動の確かめ（`CLIVersionWatcher`。engine ごとに 1 つ）: daemon は起動の 2 分後と 1 時間ごとに版ごとの実行ファイルの置き場（Claude Code は `~/.local/share/claude/versions/`、codex は上の `releases/`）の実行できる最も新しい版を見て、確かめた版の記録に無ければ同じ check を回し、通れば記録に足す（CLI を上げても人が check を回さなくてよい）。1 度に engine ごとに 1 本で、確かめる間は会話の枠の目安を 1 つ使う（空きが無ければ次の見回りまで待つ）。通らなかった版を試し直すのは 1 日 1 回まで（試した版・時刻・通らなかった最初の段は `agent-host/check-attempts.json`・`check-attempts-codex.json`、600）。通った版が記録から落ちていれば（手で回した check の書き込みと重なったとき）次の見回りで試し直す。`MachineInfo.claudeCLI`・`codexCLI`（会話が使う版・入っている最も新しい版・通らなかった版と段。codex が入っていないマシンでは `codexCLI` を出さない）を state と MCP の `health` に出す
- engine: 記録の `engine` が `claude` と `codex` の会話を動かす。どちらでもない会話（新しい版の daemon が書いた行）は、起こさずに止まった会話として state に出し、送信・回答・操作は 409 `invalid_request` で断る。host にその key の子が生きていても、止めも引き取りもしない（その版の daemon に戻したときに引き取る）。Kit は知らない engine・問いの種類・会話の出来事の種類・流れて出る塊の種類を読んでも落ちない（engine と問いは `unknown`、出来事と塊は `unsupported` にして番号だけ進める）。アプリは開き方を知らない engine の会話を開くと案内だけを出し、知らない種類の問いにはアプリを更新するよう案内する。engine ごとに使える操作は Kit の `Conversation.Engine.supports`（制御の種類と、フォーク・巻き戻し・画像・ターンの後に送る）で、無い操作は 409 `engine_unsupported`（params `engine`）
- codex の会話（`CodexConversation`）: 会話ごとに `codex app-server`（stdio。確かめた版の codex）を host の子にする。`initialize`（`experimentalApi`）→ `initialized` → `thread/start`（新しい会話）か `thread/resume{excludeTurns}`（戻す）。thread の ID は `thread/start` の応答で決まるので、それまで記録の会話 ID は会話の id で、応答で thread の ID に替える（`switchConversationSession`）。案内は `developerInstructions`、taskboard の MCP は `config` の `mcp_servers.taskboard`（点区切りの鍵。表ごと渡すとユーザーの設定の MCP の server が消える）に `TASKBOARD_CONVERSATION_ID` の env 付きで入れる。権限のモードは承認の方針と sandbox に読み替える（`CodexPermissions`。既定の bypassPermissions は `never` と `danger-full-access`、plan は `on-request` と `read-only`、ほかは `on-request` と `workspace-write`）。承認の方針・モデル・effort は turn ごとに `turn/start` で渡し、`collaborationMode`（experimental）も毎 turn 載せる（権限が plan なら `mode: plan`、ほかは `default`。settings の model・reasoning_effort は会話の値で、`developer_instructions` は null。model は記録か thread を開いた応答の値で、分からなければ載せない。断られたら欄なしで送り直し、その子の間は載せない）。権限を替えて sandbox が変わったときだけ次の turn に `sandboxPolicy` を付ける。送る発言は `clientUserMessageId` に uuid を載せ、生成中なら codex の待ち行列（`thread/queue/add`、experimental）に入れて受付を `queued` にする。待ち行列は codex の状態の DB に残り、thread が空くと codex が先頭を自動で始める（中断で空いたときは始めず、次の turn が普通に終わるまで止まる）。最後の turn が中断で終わり、turn が無く、待っている発言があれば、会話の様子に `queuePaused: true` を載せ（ほかのときは載せない）、次の turn が始まるか待っている発言が無くなれば消す。アプリは待機中のメッセージのカードに「生成を停止したため、自動では送信しません。」と［送信を再開］（先頭の発言の `send_now`。空いているので `thread/queue/start` になる）を出す。始まった発言は userMessage の item の clientId で `started` にする。`thread/queue/changed` と、引き取ったとき・thread を戻したときに `thread/queue/list` で読み直し、一覧にある発言を `queued` にし、読む前に待っていて一覧から消えた発言は codex が始めたとして `started` にする。状態の DB が無い codex（「user message queue is unavailable」で断る）では生成中の発言を `turn/steer` で今の turn に足し、turn が無い・替わっていたら（「no active turn to steer」「expected active turn id …」）`turn/start` で送り、圧縮・review の turn で足せない・ほかの断りは送れなかったことにする。承認の要求（コマンド・ファイル・権限）は問い `codex-<要求の id>` にし、`serverRequest/resolved` で消す。コマンドの要求の `availableDecisions`（experimental の欄）のうち文字列の答え（accept・acceptForSession・decline・cancel）は問いの `decisions` に載せ、答えの `decision` をそのまま返す（出していない答えは 400。選択肢の無い要求は `decision` を省いた `allow` の許可か拒否で、accept か decline）。acceptForSession は同じコマンドをこの会話の間は聞かずに通し、cancel は拒否してターンを止める。MCP の server からの問い（`mcpServer/elicitation/request`。MCP の `elicitation/create` と同じ形）は、Claude の会話と同じ Kit の問い（`kind: elicitation`）にし、答えを確かめて `{action, content}` で返す（url の開く先の全文は state に載せず、`control` の `elicitation_url` の応答にだけ返す。別の thread の問いは断る）。入力の問い（`item/tool/requestUserInput`。Plan モードで使われる）は Kit の質問（`kind: question`。問いの id は codex の問いの id、選択肢が null の問いは選択肢なし、`isSecret` は `AskQuestion.isSecret`）にし、答えは `AskQuestion.mismatch` で確かめて `{answers: {<問いの id>: {answers: [選んだ label…, 自由記述]}}}`（答えた問いだけ）で返す。秘密の問いの答えは state・ログ・記録に残さない。`plan` の item と `item/plan/delta` は assistant の発言にし、`turn/plan/updated`（ToDo の一覧）は画面に写さず捨てる。ほかの答えられない要求（動的なツールなど）は method が無いとして断る（控えの読み直しの間に見たものは、読み終えても解決していなければ断る）。こちらの要求の id は起こすたびに変える世代つきの文字列で、前の daemon の要求への応答は捨てる。子の thread（サブエージェント）の通知は会話の様子・問いに混ぜず、終わった item だけを子を起こした行の下に写す（下の「チャットのサブエージェント」）。費用はターンの後の `account/usage/read{threadId}`、トークンとコンテキストは `thread/tokenUsage/updated`。止めるときは生成中なら `turn/interrupt`、次に入力を閉じる（app-server は stdin が閉じると終わる）。圧縮は制御の `compact`（codex だけ。Claude の会話は断り、CLI の `/compact` を文で送る）で `thread/compact/start` を送る（空いているときだけ。生成中は 409 `conversation_busy`）。圧縮は codex の turn として動き、様子は `contextCompaction` の item で出し、`thread/compacted` が届いたときも消す。レビュー（アプリの `/review`）は制御の `review`（codex だけ。Claude の会話は断り、CLI の `/review` を文で送る）で `review/start` を今の thread に送る（`value` が無ければ `target` は `uncommittedChanges`、あれば `custom` の `instructions`。空いているときだけ。生成中は 409 `conversation_busy`）。レビューも codex の turn として動き、`enteredReviewMode`（`review` は対象の説明）と `exitedReviewMode` の item を印の行にする。指摘の本文は終わりの後の agentMessage で届くので、終わりの印には入れない（`exitedReviewMode.review` にも同じ本文が入る。codex の `core/src/tasks/review.rs`）。ほかに写す item（0.162.1 の型）は、`imageView` を Read の組（文はパス）、`dynamicToolCall` を「namespace.tool」の組（結果は `contentItems` の文）、`imageGeneration` を ImageGeneration の組（文は `revisedPrompt`、結果は `savedPath`。`result` の base64 は写さない。`failure`（利用枠の上限）は失敗の結果）にする。新しい thread（アプリの `/new`・`/clear`）は制御の `new_thread`（codex だけ。Claude の会話は断り、CLI の `/clear` を文で送る）で、子を止めて記録の会話 ID を会話の id に戻し（`switchConversationSession`。前の thread は会話のタスクに結んだまま）、起こし直して `thread/start` を送る（1 つの子に 1 つの thread なので、同じ子で thread を替えない）。控えは捨て、`reset` を流す。生成中・問い・裏のターミナルが残っている間は 409 `conversation_busy`。履歴は `thread/items/list` を新しい順に読み（頁の中は古い順。人の発言は送った uuid）、フォークは `thread/fork`（発言の turn まで。`lastTurnId`）で写した thread を新しい会話で戻す。どちらも、会話が動いていればその app-server に、止まっていれば 1 本だけ起こした app-server（`CodexOneShot`）に送る（フォークを動いている app-server で作ると、その app-server が新しい thread の書き手になり、新しい会話の resume が書き手の lock で断られる）。thread を戻すときに「already has an active writer」で断られたら、1 秒おきに 5 回まで試し直す。MCP の `session_start` は `kind: codex` で codex の会話を起こす（モデルと effort は codex の名前のまま）。巻き戻しはまだ無い

- 利用枠の上限の前に区切る: Claude の会話は、最後に受けた `rate_limit_event` の窓（`five_hour`・`seven_day` の `utilization` と `resetsAt`）を持ち、誤りでないターンの終わりにどちらかの窓が設定の閾値（`usagePause`。既定は 5 時間 90%・7 日 99%）以上なら区切る（`UsagePauseRule`）。両方が越えていれば戻るのが遅い方まで待つ。待ちは上限と同じ `limitResumeAt`（戻る時刻の 60 秒後）で、記録の `limitPaused`（migration v28）を立てて上限で切れた待ちと見分ける（daemon が起き直しても同じ）。待つ間は上限と同じく回答・知らせを入れずに溜め、自動で止めず、空いた会話の圧縮もしない。区切っても圧縮は送らない。時刻を過ぎたら（上限の待ちと同じ 30 秒ごとの見回り）続きの発言は送らずに待ちを消し、入力待ちに入ったときと同じく溜まった回答・知らせを届ける。人か agent が発言する・止める・`cancel_limit_resume` で待ちを消すのも上限の待ちと同じ。区切った・待ちを解いたは、それぞれ `conversation paused for usage`・`usage pause ended` の 1 行をログに出す。区切るのはターンの終わりだけで、長いターンの途中では区切らない。定期起動の回の会話（ターンを終えたら閉じる）と codex の会話は区切らない。アプリは会話の画面に「利用枠が残り少ないため、HH:mmまで待ちます。」と［取り消す］を出す

- 知らせの印: taskboard が会話に人の発言として入れる文（委譲先の知らせ・リンク・監視・予定・利用枠の続き・`session_prompt`）は、1 行目を `<!-- taskboard: <種類> key=value … -->` にする（Kit の `TaskboardNotice.marker`。種類は `delegate`・`link`・`watch`・`wake`・`limit_resume`・`session_prompt`、値は空白を含まない id と番号だけ）。質問の回答とレビューも 1 行目に印（`answer`（`task`・`ask`・`doc`）、`review`（`task`））を付ける。人の答えなので、通知の頭の文（`[taskboard 通知]`）と送り主の項目は付けず、アプリは回答を人の吹き出しのまま畳む（`FeedbackText.forPrompt`）。アプリは 1 行目の印で見分けて人の吹き出しにせず畳み、開いた全文から印の行を外す。知らない種類の印は人の発言として出す。印の無い文（前の版の daemon が入れて履歴に残ったもの）は、印の次の行と同じ頭の文で見分ける。MCP の `session_prompt` は、渡された文の頭の印を外してから、印（`from`・`task`）・`[taskboard 通知] 別のセッションからの発言`・`- 送り主: 会話 <id の先頭 8 字>「<題>」（#<番号>）。人の発言ではない`（host の会話でなければ `taskboard の外のセッション`）・「本文:」の下に文、の形で送る
- 空いた会話の圧縮: Claude の会話は、返事（誤りでないターンの終わり）の後に 50 分空いたら、daemon が `/compact` を発言として送る（1 分ごとの見回り。prompt cache の 1 時間が切れる前に縮め、次の発言で書き直すキャッシュを減らす）。送るのは、空いていて（自動停止と同じ `isResting`。画面に出ているかは問わない）、56 分を過ぎておらず、`get_context_usage` の Messages の行が 3 万トークン以上の会話だけ。1 つの空きで見るのは 1 回で、送らなかった空きでは後で大きくなっても送らない。圧縮のターンの終わりからは数えず、次の返事から数え直す。止まった会話は起こさない。daemon を入れ替えると、その時の空きは数えない。利用枠で区切って待っている間は、この圧縮はしない（区切るときに要れば圧縮する。上の「利用枠の上限の前に区切る」）。codex の会話は圧縮しない
- 止める方針: 止めてよいのは、動いていて空いていて（生成中・問いの待ち・答えている途中・起こしている途中でない）、どの接続も購読しておらず、裏のタスク（`task_started`・`task_updated`・`task_notification` で数える）が無いと分かっていて、cutoff より前から使っておらず、タスクに結ばれている会話だけ。host の控えから daemon が捨てた所（`trimmedThrough`、migration v17）より先が `gap` で落ちたら、裏のタスクの数が分からない会話として、プロセスが終わるか CLI の task の一覧（`background_tasks_changed`）が届くまで止めない。自動停止（`IdleReaper`）は設定の `idleStopMinutes` で止める。止まった会話に送る・回答を届けると、`--resume` で起こしてから入れる。止める・終わらせるは、その時の世代（起こし直した回数）を取ってから進め、途中で起こし直した新しい子には signal を送らない。問いの defer は既定（`auto`）では、購読している接続がある会話は defer せず、誰も見ていない会話は defer で終える（`control` の `defer_questions` で on・off に替えられる）。1 つの message で 2 つ以上のツールを呼んだときと、裏のタスクが動いている（数が分からない）間は、on でも defer しない（裏のタスクがあるとプロセスが終わらず、CLI はその知らせで次のターンを始め、問いを内部の誤りの結果で埋めて先へ進む。2.1.316 で、記録に残った問いに答えられず、止める指示も閉じた入力に書けずに起こし直しになった）
- 圧縮中: 会話の様子の `compaction`（`startedAt`・`outputChars`）は、圧縮している間だけ載る。Claude Code は `system/status` の `status: "compacting"` で始まり、自動の圧縮では要約の字数（`compact_output_chars`）が増えるたびに同じ行が届く（様子に流すのは 1 秒に 1 回まで。手で送った `/compact` には字数が無い。2.1.304 の実測と型）。`status: null`・`compact_boundary`・`result`・プロセスの終了で消し、`compact_result: "failed"` なら会話に「会話を圧縮できませんでした」の知らせの行を出す（`compact_error` はログだけ）。codex は `contextCompaction` の item の `item/started` から `item/completed`（か `turn/completed`・終了）まで（字数は無い）。アプリは会話の末尾の生成中の block の後ろに、回る印と「会話を圧縮しています…」と字数・経過の時間を出す
- 圧縮の区切り: 区切りの行（`system/compact_boundary`）を、会話の中の区切りの印（`notice`・`compactSummary`、id は区切りの行の uuid）にする。transcript では `compactMetadata`、stream-json では `compact_metadata` の `trigger`（`auto` なら「会話を自動で圧縮しました」）と `preTokens`・`postTokens`（両方あれば「（51,832→15,968トークン）」を足す）を読む。要約の本文の行（transcript の `isCompactSummary`、stream-json では区切りの直後の `isSynthetic` の user の行で、本文は「This session is being continued…」）は出さない（2.1.310 で実測）
- API の送り直し（Claude だけ）: CLI が API に届かず（または 429・529・5xx で断られ）送り直すたびに、`system/api_retry`（`attempt`・`max_retries`・`retry_delay_ms`・`error_status`（つながらないときは null）・`error`（`overloaded`・`rate_limit`・`authentication_failed`・`server_error`・`cloud_credential_error`・`unknown`）。応答が来なかったときだけ `no_response`。利用枠の待ちの間の心拍も同じ形で届く。2.1.304 の型の説明）が届く。会話の様子の `apiRetry`（回・上限・次に送る時刻 = 受けた時刻 + `retry_delay_ms`・status・種類）に載せ、`attempt` の無い行は読み飛ばす。主の流れ（`parent_tool_use_id` が無い）の stream の行・発言・`result`、生成中でなくなること（`setPhase` が running 以外）、プロセスの終了で消す。daemon が起き直して控えを読み直す間（`replaying`）の行は載せない（古い送り直しを今のものとして出さない）。アプリは会話の末尾に、回る印と理由（つながらない・混み合い・利用枠・認証・サーバーの誤り）、「3/10回目」、次に送るまでの残りの秒（過ぎたら消す）を出す。送り直しを諦めた後の誤りは assistant の行の `is_api_error_message`（transcript は `isApiErrorMessage`）で分かり、`TranscriptParser` がその文の `ChatMessage` に `isError` を付ける。アプリは「応答を取得できませんでした」の見出しを付け、CLI の英語の文（理由ごとに違う）はそのまま添える
- 応答を待っている間（アプリ）: 生成中の Claude の会話で、書いている block も実行中のツール（入力の block・結果の来ていない呼び出し）も無い間、アプリが会話の末尾に「応答を待っています…」と待ち始めからの時間を出す。判定は手元の発言の列（`ConversationTimeline.isAwaitingResponse`）。block の間の切れ目で出し入れしないよう、1 秒続いてから出す（`ConversationTranscript.waitingDelay`）。送り直し・止まり・圧縮の行があるときは、そちらを出す
- 止まりの見張りと中断の段上げ（Claude だけ）: 生成中（`running`）で、主の流れに結果の来ていないツールの呼び出しが無いのに、CLI から行が `stall`（5 分）を超えて来なければ、会話の様子に `stalledSince`（最後に行が来た時刻）を載せる（行が来るか生成中でなくなれば消す）。5 分は、host の会話の transcript（7 日・60 本）で結果や発言の後に次の発言が書かれるまでの間が 99% 34 秒・最長 233 秒、自動の圧縮が最長 119 秒だったことから決めた。CLI は待っている間 `keep_alive` を出さない（実測）。`control` の `interrupt` は、CLI が 10 秒で応えないか、応えてから 10 秒でターンが終わらなければ（2.1.303 で、止まった CLI が interrupt に応えず running のまま残った）、TERM・KILL で止めて `--resume` で起こし直し、待ち行列にあった人の発言を送ったときの行のまま（同じ uuid で）入れ直して、会話に「応答が無かったので、Claude Codeを起こし直しました」の知らせの行を出し、`{"restarted": true}` を返す。入れ直すのは受付が `queued` のままの発言だけで、始まった・取り消された発言は入れない。アプリは止まりを会話の末尾に「応答が止まっています」と経過の時間と［生成を停止］で出す
- 止める: `POST /v1/conversations/{id}/stop` は動いていれば止めて 204（止まっている会話は、利用枠の上限の後に続きを送る予定だけを消す）。止めた会話のうち、タスクにも役目にも結ばれていない会話（Kit の `Conversation.removedOnStop`）は記録も消す（画面から開き直す道が無い）。止まっていた会話の記録は消さないので、何度呼んでも同じになる。常駐が入っているオーケストレーターの会話は 409 `orchestrator_resident`（常駐の見回りと破棄して再起動は daemon が止める）。止めた理由は記録の `lastExit` に決まった文で残す（Kit の `ConversationStopCause`。文と理由は 1 対 1 で、前の記録の読み方が変わるので文は変えない。終了コードや signal のような決まった文でないものは `unexpected`）。CLI は `taskboard conversation stop <id>`
- 消す: `DELETE /v1/conversations/{id}` は止まっている会話の記録を消して 204（動いている・起こしている・答えている途中なら 409 `conversation_running`、無ければ 404）。消した後の取得・送る・答えるは 404、購読は `removed` で終わり、host から遅れて届いた知らせで会話を作り直さない。タスクとの結び（`taskSession`）と、回答を頼んだ会話の記録は残す（タスクの履歴から会話で開き直せる）。CLI は `taskboard conversation delete <id>`
- 終了: `POST /v1/conversations/{id}/close` は、動いていれば止め、記録は消さずに終了の印（`lastExit` の「終了した」）を付けて 204（止まっている会話も受ける）。会話のシェルを閉じ、`shellId` を空にする。終了した会話と定期起動の回の終わった会話（「定期起動の回が終わったので止めた」）は Kit の `Conversation.isClosed` が true で、アプリの一覧と MCP の `session_list` に出さない（`task_get` には `closed` で出る）。人が止めた会話と同じく、画面で開いても委譲先やリンクの知らせが来ても起こさない（`ConversationStopCause.keepsStopped`）。送るか `resume` すると起き、印は次に止まったときの理由で上書きされる。オーケストレーターの会話だけは記録を消す（1 台に 1 つで、次に起こすときに記録を引くので、印を残すと終えた会話を起こし直す）。常駐が入っているオーケストレーターの会話は 409 `orchestrator_resident`。終了した会話の委譲先（`parentConversationId` がその会話）は、空いていれば（生成中・問いの待ち・裏のタスク・利用枠の上限の待ちが無い）止める（「taskboard が止めた」なので、画面で開くと起きる）。アプリの［終了］、MCP の `session_stop` の `close`（生成の途中なら `force` と `confirm` が要る）、CLI の `taskboard conversation close <id>`（生成の途中なら確かめる。端末から読めないときは `--yes` が要る）が使う

    - codex の書き込みはどれもユーザーの設定なので、その Mac のすべての codex に効く。書くたびに codex がファイルを書き直し、外した後も空の表（`[hooks]` など）が残る
  - plugin と marketplace（`plugin`・`marketplace`。両 engine。Claude Code 2.1.304 と codex 0.162.1 で実測）
    - 読む画面の `plugins`（`ConversationPlugins`）は入れた plugin・入れられる plugin・marketplace。入れられる plugin は公式の目録で数千件（Claude は 3,603 件・2MB）あるので、`value` の文字で id・名前・説明を絞り、200 件までにして総数（`availableTotal`）を添える。アプリは会話の［プラグイン］のシート（`/plugin`。Claude は `/plugins`・`/marketplace`、codex は `/plugins` も）で出し、`shownCommand`・`confirmation` が返ったときだけシートの中で確かめてから送り直す
    - Claude の会話：`claude plugin` のサブコマンド（`install`・`uninstall`・`enable`・`disable`・`update`・`configure`・`list`・`marketplace add|remove|update|list`。どれも `--json`）を、edit-* と同じ環境で会話の作業フォルダから起こす（`ClaudePlugins`。git や npm から取るので 3 分・16MB まで受ける）。結果は stdout の最後の行（前に人向けの文が出る）。id・名前・source は `-` で始まるもの・空白を含むものを受けない（オプションと読まれる）
      - 動いている CLI は plugin の変化を自分では読み直さない（入れても切っても 4 秒たって skill の一覧が変わらなかった）。daemon は書いた後に `reload_plugins` を送り、その場で入る（更新した版の中身も）ので、`needsRestart` は false
      - marketplace が決めたコマンドで入れる plugin（source が `command`）は、1 回目に CLI が `command_source_refused` と `shownCommand`（コマンドと sha256）を返して入れない。daemon は結果の `shownCommand` で返し、人が見て選んだら `acceptCommand` に sha256 を入れた要求で `--accept-command` を付けて入れる。目録かコマンドが替わっていれば CLI はまた `shownCommand` を返す
      - 外すときは `--keep-data` を付け、データの置き場（`~/.claude/plugins/data/<id>/`）を残す。ただし保存した設定（userConfig。秘密の値を含む）は `--keep-data` でも消え、入れ直しても戻らない。daemon は `configure --json` で値のある設定の名前を引き、あれば `confirmation`（`loss: options`、外す plugin と層・設定の名前・`digest`）を返して外さない。`configure` が読めない（終了コード・時間切れ・出力の上限・JSON の誤り・`configured` の型の違い）ときは、設定なしとみなさず失敗にする。層を省いたら入れた層で外す
      - 確かめた後の送り直しは `confirm: true` と `confirmDigest`（前の `confirmation.digest`）を付ける。daemon は書く直前の対象（外す plugin と層、消える設定の名前）から digest を作り直し、合わなければ（人が見た後に対象が増えた・替わった）書かずに新しい `confirmation` を返す。確かめた状態は daemon に持たない（コマンドで入れる plugin の sha256 と同じ考え方）
      - データごと消す（`purge`）は `--keep-data` を付けずに外す。いつも `confirmation`（`loss: data`）を返す
      - marketplace を外すと、CLI はその marketplace の plugin をデータと設定ごと外す。daemon は `plugin list --json` で外す plugin を決め（配列でない・項目に id か層が無い・JSON の誤りは空とみなさず失敗にする。plugin を外すときも同じ）、先にその plugin を入れた層で `--keep-data` で外し（設定があれば `confirmation`。確かめる対象は外す plugin の全部）、それから marketplace を外す。データは残った。層を付けたら、その層の plugin だけを外す。その層が marketplace を宣言していない（層の設定のファイルの `extraKnownMarketplaces` に無い）ときは、CLI は plugin を外した後で `not_configured` で断るので、daemon が書く前に `not_found` で断る
      - 途中で失敗したら（marketplace の削除の 2 件目で CLI が断ったなど）、外せた分は戻さず、入れた plugin の一覧を読み直して `reload_plugins` を送ってから失敗を返す
      - 切った plugin を切る（`already_in_goal_state`）は成功にする。入れていない plugin を外すのは `not_found`
    - codex の会話：`plugin/install`（`plugin/list` で id から名前と、ファイルの marketplace は `marketplacePath`、目録だけのものは `remoteMarketplaceName` を引く）・`plugin/uninstall`・`marketplace/add`・`marketplace/remove`・`marketplace/upgrade`（`CodexPlugins`）。有効と無効は config の `plugins` の表に `{"<id>": {"enabled": …}}` を upsert する（id の点で鍵が切れないように）。どれもユーザーの設定だけ
      - 入れた・切った・外した plugin は、動いている thread の次の turn から効いた（`needsRestart` は false）。入れた plugin のアプリでログインが要るものは `appsNeedingAuth` に名前で返す
      - codex に plugin ごとの更新は無く、`update` は入れ直す（新しい版が cache に入った）。`marketplace/upgrade` は git の marketplace だけで、ファイルの marketplace は断る（`other`）
      - codex は外してもデータの置き場を消さないので、`purge` は無い（invalid）。marketplace が決めたコマンドで入れる plugin は一覧に出ず、入れようとすると `not_found`
      - `marketplace/remove` は plugin を外さず、config と cache が marketplace の無いまま残る。daemon は先にその marketplace の入れた plugin を外してから外す。`plugin/list` の形が違う（`marketplaces` が無い・項目に id か `installed` が無い）ときは、空とみなさず書く前に失敗にする。途中で失敗したら、`plugin/list` を読み直してから失敗を返す
  - 断られたら 409 `session_command_failed` で、params の `reason` に理由の種類（duplicate・not_found・ambiguous・locked・file_error・invalid・conflict・other）だけを入れる。engine の文（CLI の stdout・stderr・JSON の error と message、app-server の message）は書いた値（規則・hook のコマンドの秘密）を引用しうるので、応答にもログにも出さない。ログに残すのは理由の種類・終了コード（app-server は JSON-RPC の code）・時間切れや上限の印だけ。成功の応答の `warnings` も、Claude の CLI の注意の文なので入れない（数だけをログに残す）
  - 設定の書き込みは MCP の tool に出さない（アプリと API だけ）。エージェントが tool で自分の権限を広げる道を作らないため。ただし同じユーザーで動くエージェントは daemon の token のファイルを読んで API を直接呼べ、設定ファイルも直接書けるので、これは境界にならない（境界は OS のユーザー。アプリ専用の資格情報は作らないと決めた、2026-10-20）
- 内訳（`control` の `context_breakdown`）: `get_context_usage` の `categories`（名前・トークン・`used`／`deferred`／`buffer`／`free`）と合計・上限・自動圧縮を始める量を `ConversationContextBreakdown` に組み直して返す（応答の全体は 85KB あり、区分のほかは返さない）。state には載せない
- コマンド: `GET /v1/conversations/{id}/commands` は、会話のプロセスが `initialize` の応答と `system/commands_changed` で知らせた一覧（`name`・`description`・`argumentHint`・`builtin`・`aliases`。プロセスが終わっても最後に受けた分を残す、`source: session`）を返す。一度も受けていなければ `.claude` の skill と command だけ（組み込みなし、`source: catalog`）。一覧が変わったら購読に `commands` を流す。名前と alias の解決は CLI に任せる
- フォーク: `POST /v1/conversations/{id}/fork {requestID, messageID?, prompt?}` は、同じタスク・cwd・モデル・effort・権限・題の会話を作ってすぐ起こし（`prompt` があれば送る）、新しい会話を返す。同じ `requestID`（`forkRequestId`、UNIQUE、migration v18）は作った会話を返す。`messageID`（`#n` は落とす）の行は元の今の transcript の末尾 4MB から探し、無ければ 404（kind `message`）。省くと作る時点の末尾の行（送らずに止まって起こし直しても同じ地点）で、元が生成中なら 409 `conversation_busy`。元がまだ送っていないフォークなら、その写す元の地点までの行から選ぶ（無ければ 409 `conversation_not_sent`）。新しい Claude の会話 ID は daemon が振る
- 巻き戻し: `POST /v1/conversations/{id}/rewind {messageID, expectedAgentSessionID, files, dryRun}` は、人が送った発言（`messageID`）の前まで会話を戻し、`files` なら作業フォルダのファイルも戻す。`expectedAgentSessionID` が今の Claude の会話 ID と違えば 409 `conversation_changed`（古い画面からの要求と、送り直しの 2 回目）。生成中・ほかの操作の途中・裏のタスクが動いているか数が分からない間は 409 `conversation_busy`、問いを待つ間は 409 `question_pending`。戻せるのは最後の圧縮の区切りより後の発言だけで、それより前の発言は 400 `invalid_request`（dry run も同じ。アプリは前の発言に巻き戻しを出さない）。`dryRun` は会話を変えず、`files` なら `rewind_files {dry_run: true}` の結果（`canRewind`・`error`・`filesChanged`・`insertions`・`deletions`）を返す（止まった会話は下の補助のプロセスで聞く）。本番は、会話のプロセスを止め、1 つの transaction で記録を新しい Claude の会話 ID に替える（`previousSessionId` に今の ID、`pendingForkSessionId`・`pendingForkAt` に今の ID と発言の親、`rewindFilesPending`。最初の発言まで戻すなら新しい会話として始める）。次の起動はフォークと同じ引数になる。ファイルは記録を替えた後で、別の host の key（`<会話の id>-rewind`）の補助のプロセス（`--resume <前の ID>` と checkpoint の環境変数。hook は付けない）が `initialize` の後に `rewind_files` を送って戻す。補助のプロセスが終わるまで前の ID の予約をその key で持つ（その間にほかの起動が同じ会話を起こせない）。CLI がはっきり断ったら（`canRewind: false`・制御要求のエラー・起こせない）記録を操作の前に戻して 502。結果が分からなければ（応答が無い・補助のプロセスが終わった）巻き戻したまま `rewindFilesPending` を残し、会話の様子に `rewindIncomplete` を出す（ファイルだけが戻って会話が戻らない状態を作らない）。daemon が途中で終わったときも同じで、補助の key は記録の無い子として繋ぎ直しで止まる。`rewindIncomplete` は次に送るか元に戻すと消える。応答の `draft` は戻した発言の本文（アプリは入力欄に戻す）、`skippedLinks` は戻せなかったリンクの数。購読には `reset` を流し、アプリは手元の履歴を捨てて取り直す
- 巻き戻しを元に戻す: `POST /v1/conversations/{id}/rewind/undo {expectedAgentSessionID}` は直前の巻き戻しを取り消して前の Claude の会話 ID に戻す（会話だけ。ファイルは戻らない）。1 段だけで、2 回目は 409 `conversation_changed`。前の ID がほかで動いていれば 409 `session_running`。会話の様子の `canUndoRewind` が立っている間だけ使える。元に戻すときに、巻き戻した先の ID とまだ送っていなければフォークの印（`pendingForkSessionId`・`pendingForkAt`）を記録の `redoSessionId`・`redoForkSessionId`・`redoForkAt`（v32）に取っておく
- 巻き戻しをやり直す: `POST /v1/conversations/{id}/rewind/redo {expectedAgentSessionID}` は、元に戻した巻き戻しの先の Claude の会話 ID に戻す（会話だけ。ファイルは戻さない）。もう一度元に戻せる（`previousSessionId` に今の ID）。会話の様子の `canRedoRewind` が立っている間だけ使え、無ければ 409 `conversation_changed`。元に戻した後に発言を送る（人・agent・taskboard の知らせ）か、もう一度巻き戻すと消える（送った続きを捨てないため）。巻き戻した先の ID がほかで動いていれば 409 `session_running`
- Run: `POST /v1/conversations/{id}/runs {code, language, messageID?}` はコードブロックを会話のシェルで動かし、`ConversationRun` を返す（`ConversationRuns`）。シェルは会話と種類（bash・zsh・fish）ごとに 1 本、agent host の擬似端末（key は `run-<会話の id>-<種類>`、幅 200）で起こしたままにし、コードを 0600 のファイル（support ディレクトリの `runs/`）に書いて `.`（fish は `source`）で読ませるので、変数と cd が次の Run に残る。札とシェル: bash・sh は bash、zsh は zsh、fish は fish、shell・console はログインシェル（bash・zsh・fish でなければ bash）。ログインシェルと同じ種類ならその実行ファイル、違えば `/bin/bash`・`/bin/zsh`・PATH の fish（無ければ 502）。ほかの言語は 400。起こすときは対話モード（bash `-i`、zsh `-i -o histignorespace`、fish `-i --private`。`-l` は付けない）で、環境は会話の CLI と同じログインシェルの環境に `TERM=dumb`（fish 4 は dumb でなければ DA1 の答えを待つ。来た DA1 には Run の外でだけ答える）。最初の 1 行で履歴を書かせず、ジョブ制御を切り（Ctrl-C で行の全体を止めるため）、`exit` でシェルが終わるときに終了コードの目印を出させる。Run の行は始まり・終わり（終了コード）の目印（`\x1eTB:<種類>:<id>\x1e`）でコードを挟み、その間の出力から端末の制御の列と CR を落としたものを出力にする。標準入力は `/dev/null`。1 本のシェルで同時に動かすのは 1 つ（409 `run_limit`、params の `limit` は 1）。取り消し（`DELETE /v1/conversations/{id}/runs/{run}`、`cancelled`）・10 分の打ち切り（`timedOut`）・daemon の SIGTERM では Ctrl-C を送り、停止の目印の行を 300ms ごとに書き直す（zsh は Ctrl-C で先に打った入力を捨てる）。5 秒たっても目印が来なければシェルを閉じる。コードの `exit` とシェルを閉じたときは次の Run で新しいシェルを起こす。`POST /v1/conversations/{id}/runs/reset` は会話のシェルを全部閉じる（動いている Run は `cancelled`。アプリの［シェルを再起動］）。会話の終了と削除でも閉じる。daemon の普通の終了では閉じず、入れ替えた後の最初の Run で購読し直して、ためた出力の最後の目印で空いているかを決める（Run の途中か目印が無ければ閉じて起こし直す）。host が起き直したらシェルは無くなり、動いていた Run は失敗にする。出力は 1MB まで（超えたら `truncated`）、記録は会話ごとに直近 20 件をメモリにだけ持つ。出力の続きは 100ms ごとにまとめて購読に `run` で流し、控えには積まない（長い出力で発言が控えから落ちないように。アプリは購読し直したら、動いている Run を `GET /v1/conversations/{id}/runs/{run}` で取り直す）。終わったら差分を取り直す。CLI は `taskboard conversation run`・`run-cancel`
- 事前起動: `POST /v1/conversations/prewarm {cwd, model?, effort?, permissionMode?}` は、起動の画面を開いた時点で、その条件の会話のプロセスを先に起こして `initialize`（hook の登録と MCP の接続）まで済ませる（204）。マシンに 1 本だけで、DB に記録は作らず、会話の id と Claude の会話 ID を先に振って、枠と会話 ID の予約を持つ。目安の上限に空きが無ければ何もしない（温めるためにほかの会話を止めない）。同じ条件なら捨てる時を延ばすだけ。違う条件の prewarm・違う条件の `POST /v1/conversations`・120 秒では、止め終えて枠と予約を返してから次を起こす（2 本が同時に枠を持たない）。同じ条件（cwd・モデル・effort・権限）の `POST /v1/conversations` は、起き終えるのを待ってから記録を作り、その子を会話として引き取る（`initialize` は送り直す）。子の env に `TASKBOARD_CONVERSATION_ID` があるので、settings.json の SessionStart の hook は何もしない（記録の無い会話 ID でタスクを作らない）。host に繋ぎ直しただけなら止めずに購読し直し、host が起き直したら終わったものとして枠と予約を返す。daemon が起き直したら、記録の無い host の子として止まる
- 入力欄の `@` の候補: `GET /v1/conversations/{id}/workfiles?q=<打った文字>&limit=` は、会話の cwd のファイルとフォルダ（フォルダは末尾 `/`）から `q` にあいまい一致するものを `limit` 件（1〜20、既定 8）返す。受けるのは打った文字（100 字まで）だけで、引く場所は会話の記録の cwd に限るので、パスは受けず `..` も要らない。一覧は `@` を打ったときに作り（見張りはしない）、cwd ごとに 10 秒だけ控え（6 か所まで）、同じ cwd への続けての要求は走っている 1 本にまとめる。git の repo は `git ls-files --cached --others --exclude-standard`（.gitignore に従う。cwd が repo の下の 1 フォルダならその下だけ。出力 16MB・10 万件まで）、repo でなければ歩く（`.git`・`node_modules`・`.build`・`DerivedData` などは入らず、深さ 8・2 万件・2 秒まで。シンボリックリンクはたどらない）。上限に達したらそこまでの分で引き、応答の `truncated` を true にする。歩く・並べる処理は専用のキューで回し、actor と協調プールを塞がない。返す前に消えたファイルを外す。送る文は `@パス` のまま（Claude Code も Codex もパスの文字を読む）
- 会話をまたいだ全文検索: `GET /v1/conversations/search?q=<語>&limit=`（`q` は 200 字まで、`limit` は 1〜100・既定 20。範囲の外は 400。索引が無ければ 503）は、空白（全角を含む）で区切った語（8 つまで）をすべて含む発言を、大文字と小文字を区別せずに引き、会話ごとに一致した最新の発言を 1 つ（`messageID`・`role`・`at`・一致の前後の 1 行の抜粋・その会話の一致の数）、一致の新しい会話から返す。`indexing` は最初の見回りを終える前（まだ載っていない会話がある）。索引は migration v33 の `conversationSearchEntry`（発言の本文。会話を消すと消える）と、その FTS5 の表 `conversationSearchText`（trigram。本文の表を元にして trigger で揃える）と、読んだ所の `conversationSearchSource`。足すだけで、ほかの表は変えない。3 字以上の語は FTS5 で、2 字以下の語は本文を順に見て引く（trigram は 3 字に満たない語を引けない）。載せるのは履歴に出る発言のうち人の発言と返答の文だけ（ツール・思考・差し込まれた文・サブエージェントは載せない。1 発言 5 万字まで）。Claude の会話は履歴と同じ transcript の並びを前に読んだ所から読み足し、並びが替わったら（フォーク・巻き戻し・`/clear`）外れた transcript と写し元の地点より後ろの発言を消す。codex の会話は履歴（`thread/items/list`）を新しい方から、載せた発言に当たるまで読む（動いていない会話は app-server を起こして読むので、読むのはターンを終えて記録が替わったときだけ）。読み足すのは `ConversationSearchIndex.run` の 1 本で、15 秒ごと（会話が入力待ちになれば 1 秒で）に、記録が替わった会話と入力待ちになった会話を読み、10 分ごとに全部を見回る。書き込みは 1MB ごとのトランザクションに分け、DB は WAL なので読みはこれを待たない。索引は記録から作るので、いつ捨ててもよい。起動の後に 1 度だけ FTS5 の `integrity-check` で索引と本文を突き合わせ（この間は DB の書き込みを握る。この Mac の transcript を全部載せた 106MB で 2.2 秒）、食い違っていれば 3 つの表を空にして初めから読み直す。手で作り直すのは `taskboard conversation rebuild-search`（`POST /v1/conversations/search/rebuild`、daemon の token だけ。204 を返し、空にするのは次の見回りの頭）。どちらも読み終えるまで `indexing` が立つ。壊れた索引に本文を消す trigger の `delete` を当てると malformed で失敗するので、空にするときは trigger を外して本文を消し、`rebuild` で索引を空にしてから trigger を戻す
- 差分: `GET /v1/conversations/{id}/diff` は cwd を含む git の根で HEAD（初めのコミットの前は空の tree）と作業フォルダを比べ、ブランチとファイルごとの状態（rename・copy の元、追跡していないファイルの行の数は 1MB まで・500 件まで数える）を返す。git の外なら `isRepo: false`。`?scope=`（Kit の `ConversationDiffScope`）で比べる相手を替える: `all`（既定。今の通り）、`unstaged`（index と作業フォルダ。status の Y の欄が変わったファイルと追跡していないファイル）、`staged`（HEAD と index。X の欄が変わったファイル）、`branch`（`merge-base HEAD <base>` と作業フォルダ。`<base>` は `refs/remotes/origin/HEAD`、無ければ main・master・origin/main・origin/master の順に初めにあるもの。`git diff --name-status` のファイルと追跡していないファイル）。応答の `scope` と、branch で比べたブランチの `base`（無ければ nil でファイルは空。初めのコミットの前も同じ）。前の版の daemon の応答は `scope` が無く、Kit は `all` と読む。ほかの値は 400。会話の様子の `diff` に入れるのは `all` の要約だけ。`GET /v1/conversations/{id}/diff/file?path=&scope=` は 1 ファイルの unified diff を 1MB まで（超えたら最後の改行で切って `truncated`）。`path` はその範囲の今の差分に出た path か rename の元だけ受け、`..`・絶対 path・空は 400。git は `GIT_OPTIONAL_LOCKS=0`（agent の git と index.lock を取り合わない）で動かし、1 回 5 秒で打ち切る。会話の様子の `diff` は、起こした後・ターンの終わり・Edit・Write・MultiEdit・NotebookEdit・Bash の結果で、1 秒まとめて取り直す（取れなければ前の要約を残す。ファイルの見張りはしない）

- repo の見張り（`watch.kind` が `repo`）: `repo`（`owner/name`。github.com 以外は `host/owner/name`）に新しく出た issue・PR を知らせる（`LinkNotice.Kind.opened`。作者と label の名前だけを載せ、題と本文は載せない）。`query` は gh の検索語（1 行・256 字まで。`repo:`・`created:`・`sort:` は daemon が付けるので断る）。取るのは `GitHubSync` の巡回の最後で、GraphQL の search（`RepoWatchSearch`）を作成順の昇順で 50 件、前の回から 10 分重ねて取り、見た番号（大きい方から 500 件）で重なりを除く。50 件を超えた回は、取った中でいちばん新しい作成時刻から次の回で続きを取る。作ったときの 1 回（`syncRepoWatch`）は今あるものを見たことにするだけで、自分（gh のアカウント）が作った issue・PR は知らせない。間隔はアカウントごとに `3600 × cost × そのアカウントの repo の見張りの数 ÷ 500` 秒（60 秒より短くしない。1 時間に 500 点まで）。GraphQL の残りの点が 500 を切ったら、明ける時刻まで repo の見張りを取らない。rate limit の待ちはリンクと PR の一覧と共有する。前の様子は `watch.snapshot` に次の回の作成時刻の下限と見た番号で持つ。マージ・クローズで終えることはなく、終えるのは `once`・`expiresAt`・届け先が無いとき・取り消し。repo・host・検索語・届け先が同じ有効な見張りを作ると、それを返す

- コマンドの見張り（`watch.kind` が `command`、migration v36）: このマシンで決めたコマンドを回し、結果が条件に合ったら届け先へ知らせる（Claude Code の Monitor を会話の外で回すもの）。回すのは `CommandWatcher` で、常駐するのは 5 秒ごとの見回りだけ（コマンドを回している間だけ子のプロセスがいる）。`WatchCreateRequest.command`（`CommandWatchSpec`）に `command`（4,096 バイトまで）・`cwd`（在るディレクトリの絶対パス。省くとホーム）・`condition`・`pattern`・`intervalSeconds`・`timeoutSeconds`。条件は `succeeds`（終了コード 0）・`fails`（0 以外か打ち切り）・`matches`（出力に `pattern` の正規表現が合う。行ごとに `^` `$` が効き、最初に合った行を添える）・`changes`（出力と終了コードの SHA-256 が前の回と違う。1 回目は元にするだけ）・`finishes`（1 回だけ回し、終わったら結果を届ける。`once` になり、間隔は持たない）。`succeeds`・`fails`・`matches` は、前の回が合っていなかった（1 回目は合っていなかったとみなす）ときだけ届ける。間隔は前の回が終わってから 30〜86,400 秒（既定 60）。打ち切りは既定 60 秒（上限 600）、`finishes` は 3,600 秒（上限 86,400）で、プロセスグループに TERM、5 秒後も残れば KILL。`/bin/bash -c` で、標準入力は `/dev/null`、標準出力と標準エラーを 1 本にまとめ、会話と同じログインシェルの環境で回す（`CommandProcess`）。持つ出力は先頭から 1MB、届けるのはその末尾 2,000 字。有効な command の見張りは 20 件まで、同時に回すのは 4 本まで。DarkWake の間は回さない（`SystemPower.isFullWake`）。前の回の様子（合ったか・digest・`finishes` を始めた時刻）は `watch.snapshot` に、各回の結果（`Store.CommandWatchResult`）は `watchEvent.notice` に JSON で持つ。`finishes` は始める前に始めた時刻を書き、daemon が途中で起き直したら（この daemon で始めていなければ）`interrupted` の結果を届けて終える。daemon の停止（SIGTERM）では回しているコマンドを止める。起こせなかった回は理由を `error` に残し、間隔をあけて回し直す。作れるのは daemon の token（MCP・CLI）だけで、端末の token は 403（コマンドはこのユーザーの権限で動く）。作ったらすぐ 1 回目を回す。文は `[taskboard 通知] 監視 #<id>（コマンド）に動きがあった` で、コマンドの 1 行目・作業フォルダ・条件・「結果:」の下に各回（新しい 3 回まで。終了コードと秒数、合った行、出力の末尾を中の ``` より長い fence で囲む）を載せる。コマンド・条件・届け先が同じ有効な見張りを作ると、それを返す。`GET /v1/state` と `watch.updated` でほかの見張りと同じく配り、アプリはタスクの［状態］の「監視」に出す（題はコマンドの 1 行目、条件と間隔を添える）。Kit は見張りを 1 件ずつ読み、知らない種類を飛ばす（7cf90c51 より前のアプリは、知らない種類の見張りが 1 件あると `/v1/state` ごと読めない）
- 子プロセス（`Subprocess.run`）は終了を `terminationHandler` で受け、終了から 1 秒で閉じないパイプは読むのをやめる。timeout では terminate、2 秒後も残れば SIGKILL（gh の孫プロセスがパイプを握って PR 取得が止まったことがある）

  - 案件の引数（`board`）は id か名前。名前は大文字小文字を区別せずに比べ、無いか重なるときは候補を返す。省くとアーカイブしていない先頭の案件
- 委譲の親子: 委譲先は会話の記録の起こした側（`parentConversationID`。上記「起動した側への通知」）で持つ。MCP の `session_start` は `notify` のときだけ付ける（上記「セッション」）。アプリは会話の［状態］に、その会話が起こした会話を委譲先として並べる（`MachineState.delegates(of:)`）
- 端末の中継（`ConversationShells`）: `/v1/terminal/{id}` の WebSocket は会話のシェル（`shell-` で始まる id）だけを受け、ほかの id は理由 `pane_not_found` で閉じる。サーバ → クライアントは端末のバイト列をバイナリ frame で、制御情報（`frame` の予告・`mode`・`controller_busy`・`control_lost`・`closed`）を JSON テキストで送る。クライアント → サーバは `acquire` / `input`（base64）/ `resize` / `release`。開くと host がためた出力（1MB まで）を全画面の frame で送り（前の画面とスクロールバックを消してから描かせる）、以後の出力はそのまま流す。書き込みと擬似端末の大きさは操作権を持つ画面が 1 つだけ持ち、最後に `acquire(takeover: true)` した画面が取る（奪われた画面には `control_lost(taken_over)`）。観察中に入力が来たら、ほかに持つ画面が無ければ操作権を取ってから書き、あれば `controller_busy` を返す。過去の行は画面のエミュレータが持ち、`scroll` は受けても何もしない。未送信が 4 MB を超えた画面は `closed(queue_overflow)` で切り、再接続の最初の frame（全画面）で復帰させる
- 端末のクリック: マウスの報告のモードはシェルのアプリ（vim など）が入れ、エミュレータがクリックを SGR の列（`ESC[<0;x;yM` / `m`）で `input` に出す。アプリは操作中だけ送り、表示のみの間の報告は捨てる（`TerminalMouse.removingReports`）。Shift を押したドラッグは選択（ghostty の `mouse-shift-capture` の既定 `false`）

## iPhone・iPad への通知（APNs）

daemon は受信箱に増えた項目（アプリのローカル通知と同じ `MachineState.inboxItems` と `InboxNotification`）を、通知の登録のある端末に APNs で送る。アプリを閉じていても届く。鍵が無ければ何も送らない。

```sh
# 鍵（.p8）を ~/Library/Application Support/taskboard/apns/ に権限 600 で写し、Key ID・Team ID・環境を apns.json に書く。
# --key-file - なら標準入力から読む（ssh で別の Mac に入れるときに一時ファイルを作らない）。鍵の中身は出力に出さない
.build/debug/taskboard apns install --key-file AuthKey_XXXXXXXXXX.p8 --key-id XXXXXXXXXX --team-id XXXXXXXXXX --environment sandbox
ssh <host> '~/.local/bin/taskboard apns install --key-file - --key-id XXXXXXXXXX --team-id XXXXXXXXXX --environment sandbox' < AuthKey_XXXXXXXXXX.p8
.build/debug/taskboard apns status                # Key ID・Team ID・環境・鍵のファイルの権限
.build/debug/taskboard apns check                 # 端末の要らない確かめ方（下）
.build/debug/taskboard apns test                  # 動いている daemon から、登録のある全端末にテストの通知を送る
.build/debug/taskboard apns remove
```

- `--environment` を付けると、その環境に登録した端末だけに送る（鍵がその環境専用のとき）。省くと端末が登録した環境に送る。daemon は送るときに鍵と設定を読み、ファイルが変わっていれば読み直す（入れた後に daemon を起動し直さなくてよい）
- `apns check` は鍵で JWT を作り、sandbox と production に存在しないトークン（0 を 64 字）で 1 回ずつ送って答えを出す。鍵が正しければその環境は `400 BadDeviceToken`、Key ID・Team ID・鍵が違えば `403 InvalidProviderToken`、鍵がその環境で使えなければ `403 BadEnvironmentKeyInToken`。作者の sandbox 用の鍵は sandbox が 400 BadDeviceToken、production が 403 BadEnvironmentKeyInToken（sandbox 専用。2026-10-06 に実測）。どちらも h2 で繋がった
- 端末の登録は `PUT /v1/devices/current/push`（端末の token だけ。daemon の token は 400）。端末の行（`device`）に持ち、端末を止める（`DELETE /v1/devices/{id}`）と一緒に消える。同じトークンを別の端末の行が持っていれば、そちらの登録を消す。APNs が 410・`BadDeviceToken`・`DeviceTokenNotForTopic` を返したら登録を消す。応答の `delivering` は、鍵が入っていて環境の制限にも当たらないときだけ true
- 差分: agent host の会話を引き取るのを待ち、その時点の受信箱を基準にする（通知しない）。状態が変わったら 2 秒まとめて受信箱を作り直し、基準に無い項目を送る（応答待ちが解けてまた応答待ちになれば、また送る）。5 分ごとに snapshot から作り直す。鍵が無い間も基準は進める（鍵を入れたときに、それまでの項目がまとめて鳴らない）
- ターンの完了（`TurnWatch`）: 応答中だった host の会話（running から idle へ）を、出来事ごとに見て溜め、受信箱の項目と一緒に送る（2 秒まとめる間に始めて終えた分も落とさない）。オーケストレーター・定期起動・委譲先（親のある会話）は数えない。送るのは登録の `turns` が `background`・`always` で、種類（`kinds`）が空でない端末だけ。題は「応答の完了」、本文は会話の題か「Claude Codeが応答を終えました」で、外の値に `turn: "1"` を載せる。前面のときに出すか（`background` は出さない）は届いた端末が決める（アプリの `InboxNotifier` の `willPresent`。Mac と、APNs の届かない接続先のローカル通知も同じ）
  - `turns` は登録の任意の欄で、省けば送らない（前の版のアプリ）。前の版の daemon は読み飛ばす。daemon は列を足さず、`pushKinds` の列に `turns=<値>` の語を足して持つ（前の版の daemon は種類として読めない語を捨てる）。登録の応答の `turns: true` は、ターンの完了も送る版の印。アプリは `turns` の無い応答を返した接続先のターンの完了を、ローカル通知で出し続ける
- 権限の確認の応答待ち（会話の問い）は、通知に会話と問いの id、ツール名と中身の要約、確認の hash、「許可」「拒否」の category（［常に許可］を出せる問いは `taskboard.permission.always`、ほかは `taskboard.permission`）を載せる。答えは `POST /v1/conversations/{id}/answers` で問いの id に返す（古い通知で別の問いに答えない）
- JWT（ES256）は 40 分使い、`403 ExpiredProviderToken` なら作り直して 1 回だけ送り直す。送れなかったときは daemon のログに端末の id・トークンの先頭 8 字・status・reason を出す（JWT・鍵・トークンの全体は出さない）
