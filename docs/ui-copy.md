# 画面の文言

画面に出る日本語の決まり。規則の本体は `/writing-ui-text`（`~/.claude/skills/writing-ui-text`）で、この文書はこのアプリの用語表と、規則の当てはめ方を決める。食い違ったらこの文書が優先する。

対象は、アプリが描く文字すべて（ボタン、見出し、ラベル、説明、空状態、エラー、通知、メニュー、読み上げのラベル、`.help`）と、Kit と daemon が組んで画面に届く文（受信箱の項目の題（通知に出る）、定期起動の要約、会話の通知の行、Taskboard が会話に入れた文の見出し）。MCP の tool の説明と結果、会話へ送る文、CLI の出力、ログは対象外で、置き場と書き方は `docs/agent-copy.md` に従う（読むのはエージェントと開発者）。使わない語の表は `docs/agent-copy.md`「使わない語」にあり、画面の文にも効く。

## 語を選ぶ順番

同じ対象を指す語は、上から順に探して最初に見つかった語にする。利用者は macOS・iOS と Claude Code・Codex を毎日使っていて、同じ対象をその語で見ている。作った側の言い換え（欄、帯、札、題、畳む、起こす、知らせ）を画面に出さない。

1. macOS と iOS が同じ対象に使う語（標準メニュー、設定アプリ）。例：サイドバーを表示／非表示、ウインドウ、デバイス、デフォルト
2. Claude Desktop と Codex（ChatGPT アプリ）の日本語版が同じ対象に使う語。例：ターミナル、サイドパネル、タイトル、メモ、折りたたむ、フォーク、コネクタ、サンドボックス、エフォート
3. `/writing-ui-text` の用語表
4. 上で決まらない Taskboard の概念（案件、列、作業項目、委譲先、オーケストレーター、常駐、定期起動）は、この文書の用語表の語

`/writing-ui-text` の `terms.md` は「カタカナ語は、漢字語・和語で通じるならそちらを使う」とするが、このアプリでは利用者が見慣れた語を先に置く（2026-10-21 の見直し。調べと採否はメモリの `9n_wording_plan.md`）。

## 文体

- 説明、エラー、通知は敬体（です・ます）。文には句点を付ける
- ボタンとメニューは、押すと起きる操作の動詞にする。和語は終止形（閉じる、戻る）、「漢語＋する」は「する」を省く（保存、削除、追加）。対象を付けるときの助詞は「を」（タスクを追加）
- 見出し、画面の名前、欄のラベルは名詞にする。対象を付けるときの助詞は「の」（タスクの追加）。句点を付けない
- 状態のラベルは「未◯◯・◯◯中・◯◯待ち・◯◯済み・完了」の型にし、「〜しました」と混ぜない
- 敬語は「〜してください」「〜しました」まで。「ご確認ください」「〜してもよろしいですか」は使わない
- 主語と二人称を書かない（「あなた」を使わない）

## 表記

- 英数字と日本語の間に空白を入れない（「PRを開く」「3件」「このMac」）。数字と単位も詰める（「5MB」「45%」「2時間」）
- 疑問符、感嘆符、コロン、括弧は全角。「？」の後に文が続くときは全角の空白を 1 つ置く
- 省略は「…」を 1 つ
- 列挙は、順序に意味があれば「、」、無ければ「・」
- 文中でボタン、タブ、設定の項目を指すときは［ ］、画面のメッセージとユーザーが入力した値は「 」で囲む。階層は「［設定］>［接続先］」
- 時刻は `HH:mm`（09:30）。日付は「10/5（日）」
- 値が無い項目は空白にする（「—」を出さない）
- 長音は `/writing-ui-text` に従う（ユーザー、オーケストレーター）。ただし製品の機能名として定着した綴り（コネクタ、フォルダ、ブラウザ）は付けない
- 「ウインドウ」と書く（macOS の標準の［ウインドウ］メニューと揃える）
- 製品名は「Taskboard」。コマンド（「taskboard conversation check」）は小文字のまま

## 入力欄

- ラベルは欄の名前だけ。入力の条件は説明に書き、入力する前から見える位置に置く
- プレースホルダーには書式の見本（`https://`、`ABCD-EFGH`）だけを書く。説明と入力例は書かない
- ラベルの無い 1 行の欄（検索欄、チャットの入力欄）に限り、プレースホルダーを欄の名前に使ってよい（「検索」「メッセージ」）
- 入力の誤りは、その欄のすぐ下に出す

## エラー

事象、原因、対処の順に書く。

- 事象は「{操作}できませんでした」
- 原因が分からないときは事象と対処だけにする（「保存できませんでした。時間をおいて、やり直してください。」）
- 例外の文字列、daemon の文、英語のエラーをそのまま出さない。アプリが `UserFacingError`（`App/Sources/Design/Failure.swift`）で原因と対処の文に直す。daemon はエラーに `code` と `params` を付けて返し、アプリは `code` から文を組む（daemon の `message` はエージェントとログのための文で、画面には出さない）
- 操作の失敗は、その操作をした場所に出す。送信や保存に失敗しても、書いた文を消さない

## 空状態と読み込み中

- 空状態は「{対象}はありません」の 1 文にし、次に取れる操作があればボタンを置く
- 絞り込みの結果が 0 件のときは「条件に合う{対象}はありません」
- 読み込み中は「読み込み中…」

## 確認ダイアログ

元に戻せない操作と、ほかのデータに影響が及ぶ操作にだけ挟む。切り替えて戻せるもの（コネクタの有効と無効、端末の操作の引き継ぎ、再開できるセッションの終了、巻き戻しの取り消し、端末から会話に戻す）には挟まない。

- 題は「{対象}の{操作}」、確定のボタンは「{操作}」、取りやめは「キャンセル」
- 本文は「「{名前}」を{操作}しますか？　{影響}。」

## String Catalog

画面の文は `App/Sources/Localizable.xcstrings` に集め、全件を 1 つの表として読めるようにする（開発言語は ja。訳は持たない）。

- `Text("…")`・`Button("…")`・`Label("…")` のように SwiftUI に文字列のリテラルを渡すと、ビルドのときに抜き出される
- `String` で持つ文（`var label: String`、エラーの文、`help` に渡す変数）は `String(localized: "…")` で書く。書かないと catalog に入らない
- 失敗の事象（`UserFacingError` の初めの引数、`AppModel.fail`・`writeBlock` に渡す文）は `LocalizedStringResource` で受ける。リテラルをそのまま渡すと catalog に入り、`String` を渡すとコンパイルで止まる。事象を変数で持つときも `LocalizedStringResource` にする
- コマンドラインのビルドは catalog を書き換えない。文を足したり直したりしたら `scripts/sync-strings.sh` を回し、`Localizable.xcstrings` の差分も一緒にコミットする（Mac と iOS シミュレータ向けにビルドして抜き出し、`xcstringstool sync` で入れる。使われなくなった文は消える）
- 人の名前・ブランチ・番号のように訳さない値は `Text(verbatim:)` か `String` の変数で渡す
- 列の既定の説明（`ColumnGuide.defaultDescriptions`）はこの catalog に入れない。案件のデータとして daemon に保存され、人が設定で直し、紐づいたセッションも読む文なので、起動プロンプトの既定と同じく `Agent.xcstrings` の `agent.column.` に置く（`docs/agent-copy.md`）
- daemon が組んで画面に届く文のうち、チャットの `/` の候補の説明（`BuiltinSlashCommands`）は `Agent.xcstrings` の `ui.` に置く。UICopyTests はこの catalog の `ui.` の文にも同じ規則を当てる
- Kit が組んで画面に届く文（待ち理由、受信箱の題、状態の名前、定期起動の要約、列の既定の名前）も `String(localized: "…")` で書く。`Package.swift` の `defaultLocalization: "ja"` で Xcode が Kit の文も抜き出し、`scripts/sync-strings.sh` が App の catalog に入れる。実行のときは App の bundle から引く
- daemon の文（起動・取得の失敗、MCP の応答）は画面に出さない。アプリは daemon のエラーのコードから固定の文を組む（`App/Sources/Design/Failure.swift`）。daemon のファイルは先頭に `// ui-copy:ignore-file` と理由を書いて検査から外す
- daemon が会話の画面の通知の行に出す文（`ConversationEvent.Kind.notice`）は `Sources/TaskboardDaemon/Conversations/ConversationScreenText.swift` に集める。`Conversations/` のほかのファイルの文は agent とログのための文で、検査は読まない

## 検査

`Tests/UICopyTests` が、App と Kit と daemon の画面に届く文の文字列を全部読み、機械で見られる規則（空白、半角の記号、「無い」、「〜できない」、内部の語、エラーの埋め込み、用語表の使わない語）を検査する。`swift test --filter UICopyTests` で走る。

- 違反を残すときは `Tests/UICopyTests/baseline.txt` に載せる。新しい違反は通らない。直した違反が基準に残っていても通らない（基準を減らし忘れないため）
- 基準を作り直すのは `UICOPY_RECORD=1 swift test --filter UICopyTests`。違反を足すために使わない
