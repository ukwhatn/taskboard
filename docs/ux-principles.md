# 情報の出し方の原則

画面に何を、どの形で出すかの決まり。taskboard の利用者は、何本も並べて動かしている会話から「自分が今しなければならないこと」と「今どうなっているか」を短い時間で読み取る。そのため、画面に出す情報を「依頼」「状況」「お知らせ」の 3 つに分け、種類ごとに出し方・鳴らし方・消え方を決める。余白と部品は `docs/ui-system.md`、文言は `docs/ui-copy.md` に従う。新しい種類の項目や札を追加するときは、末尾の「追加するときの確認」を通す。

## 3 つの種類

- 依頼: 利用者が何かしないと先に進まないもの
  - 例: 質問（`ask_user`）、会話の問い（権限の確認・AskUserQuestion・計画の承認）、文書のレビュー依頼、手作業の依頼（作業項目の手作業待ち）、会話が部品で出した送る文面（承認待ち。入力欄の上と受信箱に出す）、人からレビューを頼まれた PR、タスクにリンクした自分の PR の CI 失敗と修正依頼
  - 答えるか、済ませるか、不要にするまで残る。時間では消えない
  - 通知を鳴らすのは依頼だけ
- 状況: 今何をしていて、何を待っているか
  - 例: 会話が実行中のツール、ターンの最後の応答、作業項目の待ち（承認・レビュー・CI・デプロイ・外部）、PR の CI の結果
  - 読むだけで、利用者は閉じない。状態が変われば書き換わる
  - 鳴らさない。札・カードの待ち理由・会話の状態の印に出す
- お知らせ: 過ぎた変化で、読めば済むもの
  - 例: 新しい文書、PR の変化、定期起動の回、オーケストレーターの応答、動いていないタスク、PR の取得の失敗
  - 24 時間で窓から出る（動いていないタスクは古いこと自体が中身なので窓を見ない）
  - 鳴らさない。既読にすると消える

迷ったら「利用者が何もしなかったら、この先どうなるか」で決める。進まないなら依頼、進むか変わらないなら状況かお知らせにする。

## 依頼の決まり

- 1 つの依頼は 1 つの行にする。 同じ事実から 2 つの依頼を作らない。作業項目の承認待ちを質問と別に出していたときは、1 つの質問が 4 行に重なり、回答した後も作業項目の行が残った。作業項目の待ちは状況に出し、依頼の実体は質問・会話の問い・PR・手作業の依頼のどれかにする
  - 会話が質問を出すときは `ask_user` の `work_item` で作業項目を結ぶ。taskboard が項目を回答待ちにし、回答か取り下げで作業中に戻すので、待ちの表示と依頼の状態が食い違わない
  - 手作業（実機での確認・ケーブルの接続・ログイン）を頼むときは、会話が作業項目を手作業待ち（`blocker_kind: manual`、頼む文は `blocker_text`）にする。手作業待ちだけは作業項目の待ちそのものが依頼の実体で、受信箱・入力欄の上・作業項目の行に［対応済みにする］を出す。押すと項目は作業中に戻り、済んだことが質問の回答と同じ経路で会話に届く（「taskboard で手作業を済ませました」）。応答の文だけで頼んだことは依頼にせず、会話の未読で読む
- 何を頼まれたかを、開いた先で必ず読めるようにする。 依頼の行と、押した先には原文（質問の文・権限の確認の中身・PR の題）を出す。要約や 1 行の待ち理由だけを依頼の中身にしない。会話のターンが進んだ後で「前の依頼はまだ待っている」と言われても、依頼の行から原文に戻れるようにする
- 出どころを添える。 タスク・会話・マシン・時刻を補足に出し、押すとその置き場（文書・会話・PR の欄）に移る
- 閉じ方は 3 つにする。
  - 答える: 質問・問いに回答する。回答は依頼元の会話に届く
  - 済ませる: 頼まれた作業を利用者が終えた。依頼元に済んだことを伝える（手作業の依頼の［対応済みにする］）
  - 不要にする: 依頼を閉じる。会話の依頼は会話に何も送らない
- 問いは、会話か文書を読みながら答える場所で答えさせる。問いだけを抜き出した画面や札では、何を求められているかが分からない
  - 会話の問い（AskUserQuestion・計画・MCP の問い）は会話の画面の入力欄の上のカード、文書の質問（`ask_user`）は文書の画面で答える
  - 会話が `ask_user`・`doc_publish` で文書に付けた質問は、会話の画面のそのツールの行の下に質問の数・文書名・［質問を開く］を出し、未回答の間は入力欄の上にも 1 行出す（`DocumentToolRef`・`ConversationOpenAsks`）。答えるのは文書の画面で、入口から文書へ移す
  - 札の上で答えられるのは、中身が 1 行で完結する権限の確認（［許可］・⌘Y）だけにする。質問・計画・依頼の札は［会話を開く］
  - 選択肢の違いが文で伝わらないとき（画面の形・表・コードの形）は、選択肢に見本（`AskOption.preview`。markdown か HTML）を持たせ、カードは問いごとに 1 枚を選択肢の横（入らない幅では下）に出す。出すのは、最後に押した（Mac はポインタを載せた）選択肢、選んでいる選択肢、推奨、見本を持つ最初の選択肢の順
  - 推奨は 1 つにし、［推奨］の札で示す（`AskOption.recommended`。Claude が label の末尾に付ける「(Recommended)」も推奨として読み、画面では外す）。送る答えの label は変えない
- 自動で閉じる条件を決めておく。 回答した、会話を終了した、タスクを完了・見送りの列に移した、のどれかで閉じる。終わったタスクの待ちは古い記録なので、依頼にも状況にも出さない（カードの待ち理由 `BoardTask.waitLine` と同じ）
- ［非表示］は表示の都合で、依頼元の状態を変えない。 主な閉じ方にしない。非表示にした依頼は中身が変わる（`InboxItem.revision`）とまた出る
- 利用者が解消できない項目を依頼に入れない。 自分の番の PR は、人からレビューを頼まれた PR と、タスクにリンクした PR だけにする。タスクにリンクしていない自分の PR の CI 失敗と、bot（Dependabot など）からのレビュー依頼は、お知らせと PR の一覧に出す。Dependabot の更新 4 件のレビュー依頼が、対応待ちに残り続けていた

## 状況の決まり

- 今していることを 1 行で出す。 会話が動いている間は実行中のツール、ターンが終わったら最後の応答の頭（`Conversation.lastReply`）を出し、時刻を添える
  - 出すのは見張り盤の行と札、案件のボードのカード、iPhone のタスクの一覧の 2 行目。完了・見送りの列のタスクには出さない
  - タスクの画面には出さない。すぐ下に会話そのものがあり、言い直しになる。依頼も、会話の画面の帯だけに出し、タスクの画面の上にカードを重ねない
- 待ちは「誰の番か」で色を分ける。 利用者の番は橙（`Banner` の `waiting`、`.attentionCard()`）、相手待ち（レビュー・CI・デプロイ・外部）は控えめの色（`pending`）。止まりの異常（応答なし・利用枠の回復待ち・接続待ち・異常終了）は種類ごとの語で出し、「応答待ち」にまとめない
- 失ったものが無い止まりは異常にしない。 入力待ちの間にプロセスが終わった会話（外からの kill など）は、送れば起き直して何も失っていないので、ほかの止まった会話と同じく札を出さない。異常の札は、ターンの途中で止まったものだけにする（`Conversation.stoppedInTurn`）。Studio で `pkill` が会話 12 本を一度に落としたとき、10 本は入力待ちだったのに対応待ちを埋めた
- 札は 1 つの行に 1 つ。 強いもの（依頼 → 未読 → 実行中 → PR の結果）から 1 つだけ出す（`TaskRowStatus`）

## お知らせの決まり

- 依頼に出したものをお知らせに重ねない。 依頼の行が今の状態を持つので、同じ PR の CI 失敗のお知らせは出さない
- 版・回ごとに別の項目にする。 文書の新しい版、定期起動の次の回は、前の項目を既読にしていても出る

## 端末ごとの出し方

- Mac は見張り盤（ホーム）とサイドバーの札で依頼を見つけ、⌥⌘A で次の依頼へ移る。答えるのは会話か文書の画面で、札の上で答えられるのは権限の確認（［許可］・⌘Y）だけにする
- iPhone は一覧の先頭の対応待ちの節と、タスクの一覧の札で依頼を見つける。通知（APNs）から開いた先で答えられるようにする
- どの端末でも、依頼の数と並び、閉じた結果は同じにする（受信箱の組み立ては `MachineState.inboxItems` の 1 か所だけで行う）

## 追加するときの確認

新しい項目・札・通知を追加するときは、次を順に決めてからコードに入る。決められない問いがあれば、追加する前に設計を見直す。

1. 3 つの種類のどれか。利用者が何もしなかったら何が起きるか
2. 依頼なら、原文はどこにあり、押した先で読めるか
3. 同じ事実をすでに別の項目が出していないか（出しているなら、どちらか 1 つに寄せる）
4. どう閉じるか。自動で閉じる条件と、閉じた結果を依頼元に返すか
5. 鳴らすか。鳴らすなら依頼だけで、通知の設定（`NotifyKind`）のどの種類に入るか
6. 終わったタスク（完了・見送りの列）で出さないか
7. Mac・iPad・iPhone のどこに出し、どこで答えるか
8. 文言は `docs/ui-copy.md` の用語表の語か（新しい語なら用語表に追加する）
